# Phase 4B：Career OS 决策工作台

Phase 4B 把已有的采集、证据、增量差异、资格判断和查询 API 组合成一个可运行的本地工程工作台。目标仍然是浙江、重点杭州的半体制稳定技术岗位，不是通用招聘网站；它是继续完成业务闭环的基础，不代表完整产品已经验收。

## 使用入口

在 Windows PowerShell 中执行：

```powershell
pwsh -NoProfile -File scripts/start-career-os.ps1
```

脚本会启动项目独立的 PostgreSQL 16、在源码有变化时重建应用、等待健康检查通过，然后打开 `http://localhost:8080/`。首次构建会安装锁定版本的前端依赖，耗时会比后续启动长。

停止应用并保留数据：

```powershell
pwsh -NoProfile -File scripts/stop-career-os.ps1
```

数据库默认映射到本机 `55432` 端口，避免占用常见的 `5432`。可用 `CAREER_OS_DB_PORT` 覆盖。停止脚本只停止当前项目 PID 文件记录且命令行指向当前项目 JAR 的 Java 进程；PostgreSQL 数据卷不会被删除。

## 页面与工作流

### 首次资料确认

页面提供出生年月、学历、专业、地点和可接受用工形式的资料入口。当前资料版本机制已经具备，但关键事实逐项证据、确认状态和缺失事实追问仍需补齐；在此之前不能把资料页面视为完整候选人事实验收。

### 今天

“今天”不是传统仪表盘，只显示需要处理的变化：

- 临近截止岗位；
- 新增、变更和下线批次；
- 连续失败的数据源；
- 等待人工复核的公告提案。

同一岗位没有变化时不会反复提示为新增。某一汇总分区不可用时，其余分区仍显示，并明确标记部分信息暂不可用。

### 机会池

只有解析质量为 `VERIFIED`、目标范围为 `INCLUDED` 且用工身份已经明确的岗位才进入机会池。岗位按 T1、T2、T3、排除/复核分开显示，不跨层混排；原始记录、待解析记录、待复核记录和用工身份未知记录不会被降级塞进 T3。岗位档案先展示硬性阻断，再展示适配、稳定和证据覆盖；未知条件统一标记为“待核实”。所有评分均附带“机会决策指数，不是录取概率”的边界说明。

“官网 Excel 初筛”是机会页上的独立候选区。系统从浙江、杭州官方公告下载岗位计划表，解析单位、岗位、学历、专业、年龄、职称等条件，再按已确认的候选人画像做硬条件判断与适配排序。自动解析结果一律保持 `NEEDS_REVIEW`，不会仅凭 Excel 内容自动进入可信机会池；每个附件拥有独立快照，因此同一公告的多个岗位表不会互相误判为下线。

### 更新岗位库

数据入口按可信度排序：

1. 浙江省、杭州市人社官方源，可重复触发增量采集；
2. 官方 XLS/XLSX 附件导入；
3. 官方 HTML/PDF 公告解析；
4. 低置信度结果进入人工复核，不直接进入岗位决策。

采集运行区分成功、部分成功和失败；导入使用内容指纹复用已有结果。页面同时展示原始、待复核、已核验和可信机会数量。岗位内容指纹变化后会撤销旧准入并重新进入待复核，避免过期资格结论继续排名。现有人工复核支持公告提案确认、修正、驳回和补证据；岗位级准入操作界面仍待后续补齐。

### Career OS Agent

当前入口只读取候选人资料、已准入岗位决策和证据，不改写硬资格、评分或层级。模型默认关闭，此时仍由确定性 Java 规则返回受控答案；即使启用模型，模型也只负责表达，不成为决策者。它目前是受控自然语言查询入口，不是已经完成的多工具 Eligibility Agent；缺失事实追问、字段级证据解释和完整编排仍待实现。

## 当前业务边界

本阶段解决的是“原始数据不能冒充可信机会”。完整业务 MVP 还需要：

- 候选人关键事实逐项确认并保存证据；
- 岗位硬条件和用工身份的字段级证据；
- 30—50 个 Golden Jobs 人工真值集及资格准确率验收；
- 岗位级人工准入工作流；
- Eligibility Explanation Agent 的工具编排与缺失事实追问。

因此，若历史数据库中 2291 条记录都没有完成核验，页面显示 0 个可信机会是正确的安全状态，不是采集失败。

## 验证

2026-08-20 使用杭州市人社局官方来源完成两次增量验收：首次处理 33 份公告/附件，第二次 33 份均判定为未变化，新增、变更、下线和失败均为 0。机会页的官网 Excel 初筛可展示“杭州市西溪医院 / 信息中心工作人员”等匹配结果，并保留官方原文链接和“用工身份待确认”提示。

```powershell
Set-Location career-ui
npm run verify
```
