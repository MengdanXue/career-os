# 现有实现与原始需求差距

初次审计：2026-08-14
最近更新：2026-08-20（Phase 4A）

## 结论

工程已经从“附件增量解析演示”推进为可运行的第一版“杭州/浙江稳定技术岗位职业决策 Agent”：具备确定性资格门槛、证据感知的匹配与稳定性评估、T1/T2/T3 分层、可审计版本快照、排名 API 和受控自然语言查询。它尚未完成来源扩面、跨年度趋势、提醒和申请执行闭环。

## Phase 4A 已关闭的差距

| 原差距 | 当前状态 |
|---|---|
| CandidateProfile 与决策字段 | 已实现技能、研究关键词、目标岗位族、单位偏好和版本化资料 |
| 硬资格结论 | 已实现年龄、学历、专业、届别、经验、职称的确定性门槛 |
| T1/T2/T3 分池 | 已实现；硬资格不符单独进入 `EXCLUDED` |
| 多维机会评估 | 已实现六维匹配度、七维稳定性、未知事实和证据覆盖率 |
| 可审计决策记录 | 已实现 PostgreSQL/Flyway 版本快照、维度和证据关系 |
| 决策 Agent | 已实现受控中文查询、排名工具调用、确定性回退和只读模型润色边界 |

## 必须重构

| 当前实现 | 问题 | 目标 |
|---|---|---|
| `scan_official_recruitment_sources` 只扫 S09/S10 国企源 | 偏离“事业编优先” | 首先覆盖省/市事业单位和官方附件，国企单独作为 T3 |
| `find_it_job_candidates` | 只有通用 IT 关键词相关度 | 替换为用工身份、资格判定和多维机会评估 |
| `classification.score` | 容易被误解为最终匹配分 | 仅保留为文本分类置信度，不进入最终决策 |
| 每日工作流固定导入最新 S09 附件 | 来源、附件和事件写死 | 按 source adapter 和 RecruitmentEvent 编排 |
| `employer.organization_type` | 粒度不足 | 增加主管部门、事业单位类别、国资关系和证据 |
| `position.employment_type` | 枚举有基础但没有判定证据 | 建 EmploymentIdentity 结论、依据、置信度与复核状态 |

## 尚未实现的核心能力

1. 留服认证、权威专业目录映射、社保/择业期等更复杂资格规则；
2. 候选人字段逐项确认状态和针对未知信息的交互补全；
3. 浙江/杭州各区、高校、医院和国企来源扩面，以及来源变更监控；
4. 单位经费、主管关系、政策与裁员风险事实的持续证据采集；
5. 跨年度岗位族、重复招聘、竞争度与 2027 关注信号；
6. 关注清单、截止提醒和求职状态跟踪；
7. 事业单位、AI、国企三类材料和面试准备工作流；
8. 面向普通用户的前端，以及自动投递之外的安全执行辅助。

## 优先改造路线

### P0：先让结论正确

- 固化候选人事实与未知字段；
- 增加 EmploymentIdentity 和 EligibilityAssessment；
- 对现有样本做“编制/派遣/国企 + 是否可报”验收；
- Agent 遇到未知信息时必须停止在 `NEEDS_CONFIRMATION`。

### P1：再让数据覆盖目标市场

- 接入浙江省人社、杭州市人社及代表性高校/医院来源；
- 按 2025—2026 回填；
- 建单位与岗位族历史关联。

### P2：最后做策略与执行

- 多维评分和 T1/T2/T3 关注清单；
- 2027 月度关注日历；
- 材料、笔试、专业面和 Application 跟踪。

## 当前样本的正确用途

- S01—S08：用于验证事业单位、高校、医院公告及附件解析和资格字段；
- S09—S10：用于验证国企来源、正式招聘系统、空状态和增量更新；
- 不能用 S09 的 101 个岗位代表整个杭州半体制机会池；
- 不能用“IT 关键词命中数”替代是否可报或是否值得投。
