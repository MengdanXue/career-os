# 现有实现与原始需求差距

初次审计：2026-08-14
最近更新：2026-08-20（V9–V11 Opportunity Admission Gate）

## 结论

工程基础已经可运行，但完整的“杭州/浙江半体制稳定技术岗位职业决策 Agent”仍未达到业务验收条件。现有 2291 条历史记录是原始采集数据，不是 2291 个可信机会；在它们完成解析、证据核验和目标范围确认前，正确结果应当是 0 个可排名机会，而不是把未知岗位批量放进 T3。

当前已建立强制准入门：只有 `VERIFIED + INCLUDED` 的岗位才允许进入资格判断、T1/T2/T3 排名和决策快照。工程已经解决“原始数据冒充业务结论”的正确性问题，但候选人事实、字段级证据、用工身份与真实样本验收仍需继续完成。

## V9–V11 已关闭的安全差距

| 原差距 | 当前状态 |
|---|---|
| 原始记录直接进入机会池 | 已阻断；未准入岗位不会进入资格评估或 T1/T2/T3 |
| 岗位内容变化后沿用旧结论 | 已阻断；内容指纹变化会自动重置为待复核 |
| 页面混淆采集量与机会量 | 已区分原始、待复核、已核验和可信机会 |
| API 可绕过准入直接评估 | 已返回 `409 JOB_NOT_ADMITTED` |
| 历史未知岗位被当作 T3 | 已迁移为 `RAW + NEEDS_REVIEW`，不再参与排名 |
| 旧资格写接口绕过新引擎 | 已停用并返回 `410 Gone`；新决策 API 是唯一评估入口 |
| 已核验岗位被编辑后沿用旧快照 | 关键字段重新计算指纹并撤销准入；评估事务内重新锁定岗位与准入状态 |
| 用工身份 `UNKNOWN` 被降级塞进 T3 | V10 禁止其成为可信机会；V11 会在用工身份被直接改动时撤销旧准入 |

## Phase 4A 已具备的工程能力

| 原差距 | 当前状态 |
|---|---|
| CandidateProfile 与决策字段 | 已实现技能、研究关键词、目标岗位族、单位偏好和版本化资料 |
| 硬资格结论 | 已实现年龄、学历、专业、届别、经验、职称的确定性门槛 |
| T1/T2/T3 分池 | 规则引擎已实现；只对通过准入门的可信岗位运行，现有原始数据不能视为已验收 |
| 多维机会评估 | 已实现六维匹配度、七维稳定性、未知事实和证据覆盖率 |
| 可审计决策记录 | 已实现 PostgreSQL/Flyway 版本快照、维度和证据关系 |
| 决策查询入口 | 已实现受控中文查询、排名工具调用、确定性回退和只读模型润色边界；完整 Eligibility Agent 工具编排尚未完成 |

## 必须重构

| 当前实现 | 问题 | 目标 |
|---|---|---|
| `scan_official_recruitment_sources` 只扫 S09/S10 国企源 | 偏离“事业编优先” | 首先覆盖省/市事业单位和官方附件，国企单独作为 T3 |
| `find_it_job_candidates` | 只有通用 IT 关键词相关度 | 替换为用工身份、资格判定和多维机会评估 |
| `classification.score` | 容易被误解为最终匹配分 | 仅保留为文本分类置信度，不进入最终决策 |
| 每日工作流固定导入最新 S09 附件 | 来源、附件和事件写死 | 按 source adapter 和 RecruitmentEvent 编排 |
| `employer.organization_type` | 粒度不足 | 增加主管部门、事业单位类别、国资关系和证据 |
| `position.employment_type` | 枚举有基础但没有判定证据 | 建 EmploymentIdentity 结论、依据、置信度与复核状态 |

## 尚未实现的核心能力

1. 候选人关键事实逐项确认、证据来源和针对未知信息的交互补全；
2. 岗位专业、学历、年龄、经验、届别、编制/派遣等字段级证据与人工核验；
3. `EmploymentIdentity` 用工身份结论、依据、置信度和复核状态；
4. 30—50 个杭州/浙江 Golden Jobs 的人工真值集与“是否可报”验收；
5. 完整 Eligibility Explanation Agent 的工具编排、缺失事实追问和可追溯说明；
6. 留服认证、权威专业目录映射、社保/择业期等更复杂资格规则；
7. 浙江/杭州各区、高校、医院和国企来源扩面，以及来源变更监控；
8. 跨年度趋势、关注清单、截止提醒、申请跟踪和材料/面试工作流。

## 优先改造路线

### P0：先让结论正确

- 固化候选人事实与未知字段；
- 增加 EmploymentIdentity 和字段级 EvidenceFact；
- 建立 30—50 个 Golden Jobs，对“编制/派遣/国企 + 是否可报”做人工验收；
- Agent 遇到未知信息时必须停止在 `NEEDS_CONFIRMATION`。

### P1：再让数据覆盖目标市场

- 接入浙江省人社、杭州市人社及代表性高校/医院来源；
- 按 2025—2026 回填；
- 建单位与岗位族历史关联。

### P2：最后做策略与执行

- 多维评分和 T1/T2/T3 关注清单；
- 2027 月度关注日历；
- 材料、笔试、专业面和 Application 跟踪。

## 当前样本的正确用途

- S01—S08：用于验证事业单位、高校、医院公告及附件解析和资格字段；
- S09—S10：用于验证国企来源、正式招聘系统、空状态和增量更新；
- 不能用 S09 的 101 个岗位代表整个杭州半体制机会池；
- 不能用“IT 关键词命中数”替代是否可报或是否值得投。
