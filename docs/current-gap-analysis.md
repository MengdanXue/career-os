# 现有实现与原始需求差距

初次审计：2026-08-14

最近更新：2026-08-24（个人决策正确性与目标市场覆盖验收）

## 结论

Career OS 已经是可运行、可审计的个人半体制规划与官方岗位研究台，不再只是采集工程。系统能够按用户真实画像识别“2027 应届生 + 社会招聘”双通道，区分历史公告当年的实际资格与 2027 类比资格，并在站内展示报名、资格审查、缴费、准考证、笔试、专业测试、面试和官方证据链接。

当前版本尚不能宣称完成浙江/杭州全市场覆盖。目标来源目录共 20 个：已接通 2 个、部分接通 1 个、未接通 17 个。样本不足在产品中被明确拆成“来源是否接通、事件/岗位是否解析、字段证据是否完整”三层，不再用一句“样本不足”掩盖采集缺口，也不会为未覆盖路线伪造 0 分或 0 个机会。

## 已关闭的关键产品差距

| 原差距 | 当前状态 |
|---|---|
| 用户明明满足应届条件却没有应届路线 | 已按 2027 预计毕业事实识别为目标年应届生，同时保留社会招聘通道 |
| 历史公告直接套用到 2027 | 已分离 `historicalActual` 与 `targetYearAnalog`，岗位详情同时展示两个结论和各自原因 |
| 只给官网跳转，站内看不到完整条件 | 已在岗位详情展示岗位要求、招聘流程、考试科目/状态、时间节点、证据状态和官方链接 |
| “没有核实/样本不足”无法判断原因 | 已拆为目标市场覆盖、事件/岗位解析、字段证据完整度三层 |
| 未覆盖路线显示假 0 分 | `NOT_COVERED` 路线不再返回伪造分数或代表岗位 |
| 原始记录直接进入机会池 | 只有 `VERIFIED + INCLUDED` 的岗位才能参与资格评估和 T1/T2/T3 排名 |
| 岗位变化后沿用旧结论 | 内容指纹变化自动撤销旧准入并重新进入证据核验 |
| 同一 Excel 每天重复报新增 | 已使用稳定岗位键、内容指纹和新增/变更/下线/未变化差异 |
| 画像修改后看不到影响 | 已对旧版本同批岗位按同一 `asOf` 重算，并展示新增可报/待确认/不可报差异 |
| 无可信机会时首页无事可做 | 已增加毕业、认证和考试准备的基线行动 |

## 官方源复跑结果

- 浙江省人社核心源：发现并抓取 25 个文档，22 个未变化、3 个更新、0 个误下线、0 个失败。
- 杭州市人社核心源：发现并抓取 33 个文档，27 个未变化、6 个更新、0 个误下线、1 个抓取失败，运行状态为部分成功。
- 两次真实复跑后，个人决策接口和浏览器端到端验收仍全部通过。

这证明增量键和内容指纹已经在真实官网数据上工作，但杭州市源的 1 个失败文档仍需要在后续采集中重试和归因。

## 仍未完成的核心能力

1. 接通剩余 17 个官方来源，并把浙江工商大学从部分接通提升为完整接通；
2. 补齐 59 个岗位的关键字段证据，扩大可信机会池和 Golden Jobs 人工真值集；
3. 对留服认证、境外学历时间、权威专业目录、择业期/社保等复杂规则建立更细的可执行判断；
4. 扩展高校、医院信息中心、区县事业单位和国企数字平台的专用来源适配器；
5. 增加申请跟踪、材料清单、提醒、笔试复习进度和面试复盘闭环；
6. 持续积累至少三年同口径历史数据后，再提高月份预测和路线机会频率的统计置信度。

## 后续优先级

### P0：扩大可信样本

- 修复杭州市源当前 1 个失败文档；
- 补齐已采 188 个岗位中 59 个不完整岗位的字段证据；
- 对“计算机相关 + 2027 应届/社会招聘 + 杭州稳定技术岗”建立人工验收集。

### P1：接通目标市场

- 依次接入各区人社、高校、医院和国企官方源；
- 每个来源都记录接通状态、最近成功时间、失败原因和分析覆盖量；
- 回填 2024—2026 同口径公告及附件。

### P2：从研究台走向执行台

- 2027 月度关注日历和动态提醒；
- 报名材料、资格复核、笔试、专业测试和面试任务；
- 申请状态、结果和复盘数据沉淀。

## 边界

- 当前 188 个岗位只能代表已分析的 2 个核心来源，不能代表整个浙江/杭州半体制市场；
- 129 个字段证据完整岗位不等于 129 个本人可报岗位；
- 历史可报结论只说明当年规则，2027 结果是基于目标年年龄、学历阶段和已知规则的类比判断；
- 官方链接必须保留用于最终报名和公告变更核验，但用户进行初筛时不应被迫跳出系统才能看到必要信息。
