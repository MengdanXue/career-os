# 现有实现与原始需求差距

初次审计：2026-08-14

最近更新：2026-08-24（杭州 Wave 2 Slice B：招聘生命周期关联与西湖 Excel 验收）

## 结论

Career OS 已经是可运行、可审计的个人半体制规划与官方岗位研究台，不再只是采集工程。系统能够按用户真实画像识别“2027 应届生 + 社会招聘”双通道，区分历史公告当年的实际资格与 2027 类比资格，并在站内展示公告、报名、资格审查、缴费、准考证、笔试、专业测试、面试、体检、考察、公示、聘用及官方证据链接。

当前版本尚不能宣称完成杭州全市场覆盖。目标来源目录共 28 个：真实运行态已接通 1 个、部分接通 5 个、采集失败 0 个、未接通 22 个。杭州 10 个 P0 区和 3 个 P2 县市均已建档，但本轮只完成西湖区官方列表契约、Excel 附件和生命周期路由的实际接入，其余区县仍会明确显示“未配置采集器”。样本不足在产品中被明确拆成“目标是否建档、官网是否可访问、来源是否接通、附件是否有问题、事件/岗位是否解析、生命周期是否关联、字段证据是否完整”七层，不再用一句“样本不足”掩盖采集缺口，也不会为未覆盖路线伪造 0 分或 0 个机会。

## 已关闭的关键产品差距

| 原差距 | 当前状态 |

## 官方源复跑结果

- 浙江省人社核心源：发现并抓取 25 个当前文档，24 个内容未变化、1 个更新、0 个误下线、0 个失败；25 个文档均已使用 `official-fact-fusion-v8` 重新处理。
- 杭州市人社核心源：发现并抓取 33 个当前文档，32 个内容未变化、1 个更新、0 个误下线；32 个使用 `official-fact-fusion-v8` 完整处理，1 个高层次/特殊专业技术岗位 XLS 以 `v8:partial` 入库并使运行状态为部分成功。
- 两次真实复跑后，个人决策 API 再次通过：2 个分析来源、26 个事件、188 个岗位、188 个岗位个人投影、129 个证据完整岗位；页面端到端验收仍全部通过。
- 杭州 Wave 2 Slice A 的最终独立复跑中，杭州市人社源第二次运行发现 33、抓取 33、未变化 33、新增 0、更新 0、下线 0、失败 0；数据库中“招聘单位 / 招聘岗位 / 序号”重复表头伪岗位的启用数为 0。
- 来源健康接口现在覆盖全部 28 个目标，即使尚未绑定采集器也会返回；官网访问失败与附件解析问题分别展示，未配置目标不能被标记为已接通。
- 西湖区官方附件最初因浙江政务云对象存储域名未在来源白名单而失败；V40 只为该来源精确加入已核实官方域名。修复后第一轮新增 1 个 Excel、复用 2 个公告、失败 0，第二轮复用全部 3 个文档、新增/更新/失败均为 0；Excel 形成 24 个正式事业单位岗位，其中“信息管理”研究生专业要求直接包含“计算机科学与技术”。
- 当前西湖列表三份材料没有资格复审、成绩、面试、体检、考察、公示或聘用标题，所以生命周期实测为 0。页面明确展示零；验收同时证明重复阶段行、矛盾关联和误建招聘事件均为 0。

这证明增量键、内容指纹和处理器版本触发重解析已经在真实官网数据上工作。杭州的 1 个部分成功附件不是未下载：原件已取得并保留，但其中至少一行未满足确定性岗位表导入约束，仍需补充行级错误持久化与专用表头适配后再消除该失败计数。

## 仍未完成的核心能力

2. 补齐 59 个岗位的关键字段证据，扩大可信机会池和 Golden Jobs 人工真值集；
3. 对留服认证、境外学历时间、权威专业目录、择业期/社保等复杂规则建立更细的可执行判断；
4. 扩展高校、医院信息中心、区县事业单位和国企数字平台的专用来源适配器；
5. 增加申请跟踪、材料清单、提醒、笔试复习进度和面试复盘闭环；
6. 持续积累至少三年同口径历史数据后，再提高月份预测和路线机会频率的统计置信度。
7. 将已完成的保守生命周期关联扩展到其余杭州官方来源，并积累真实的未匹配/歧义样本；系统不会猜测无法唯一关联的后续公告。
8. 建立 2027 届、境外应届、留服认证、年龄参考日、未落实工作单位/社保和专业目录的权威政策源，并对规则变化单独推送。

## 边界

- 当前 188 个岗位只能代表已分析的 2 个核心来源，不能代表整个浙江/杭州半体制市场；
- 129 个字段证据完整岗位不等于 129 个本人可报岗位；
- 历史可报结论只说明当年规则，2027 结果是基于目标年年龄、学历阶段和已知规则的类比判断；
- 官方链接必须保留用于最终报名和公告变更核验，但用户进行初筛时不应被迫跳出系统才能看到必要信息。
