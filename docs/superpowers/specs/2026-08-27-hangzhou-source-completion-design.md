# 杭州目标来源全量接入设计

日期：2026-08-27

状态：用户已批准；2026-09-07 按十八项补充要求修订。现有接入成果保留，历史机会库尚未通过六级验收。

## 1. 目标

建立能够证明覆盖范围、发现漏采、保留历史变化的杭州机会数据底座，支持 2024—2026 历史筛选和 2027 招聘增量采集。原规划 28 个来源为最低接入范围；V77 基线已扩充到上一轮报告的 30 个来源，实际总数以当次注册表快照为准。必要时继续增加官方主来源、栏目、验证源和政策源。

“来源接入完成”不等于伪造历史完整性。若官网本身没有可遍历档案、旧域名已经失效、栏目迁移导致官方总量无法证明，来源可以完成当前采集器接入，但对应年份必须保持 `PARTIAL`，并记录可验证的停止原因和缺口证据。

## 2. 完成标准

每个目标来源必须同时满足以下条件，才可以从 `NOT_CONNECTED` 或 `FAILED` 转为已接入状态：

1. 官方入口、详情链接模式、分页契约和附件域名已经核验。
2. 采集配置已登记，且只允许访问该来源明确列出的官方主机和路径。
3. 一次真实增量运行成功发现并处理候选公告；若当前窗口确无候选公告，必须通过已核验的空列表契约证明，而不是把首页零链接当成成功。
4. 第二次增量运行不产生重复新增；相同内容必须计入 `unchanged`。
5. 2024、2025、2026 三个年度均执行历史回填，并保存页数、过滤数、失败数、最早/最晚发布日期和停止原因。
6. 遍历末页只是年度覆盖证据之一；必须同时完成必需栏目审计、年度时间范围证明、文档对账和官方渠道交叉核验，才允许按第 11 节授予相应完成级别。
7. 招聘公告与资格复审、成绩、笔试、面试、体检、考察、递补、公示、聘用等生命周期材料分别保存，并只在唯一匹配时关联。
8. 岗位表附件能够解析；非岗位工作簿、专业目录和说明表不得制造伪岗位或失败噪声。
9. UI 能展示来源状态、年度覆盖、失败原因、生命周期计数、岗位必要条件和官方证据链接。

`NOT_CONNECTED=0`、`FAILED=0` 与真实幂等复跑只证明接入层验收。`PARTIAL` 可表示已解释的历史或文档缺口，不能据此宣布杭州机会历史库完成。旧报告中的 `COMPLETE` 和 `NO_TARGET_RECORDS` 必须重审；不得直接映射到新版 Level 2 或 `VERIFIED_NO_DATA`。

## 3. 方案选择

### 3.1 采用方案：来源契约驱动的适配器联邦

在现有采集领域模型和增量指纹机制上扩展来源契约。共享分页、发现、下载、解析和覆盖证明能力，差异通过来源配置表达；仅对无法由通用契约表达的页面增加小型专用适配器。

优点：

- 同类官网共享一套经过测试的实现。
- 每个来源仍有独立的主机白名单、链接正则、分页上限和完成证据。
- 新来源接入以配置为主，不会复制二十套爬虫。
- 失败和完整性结论继续进入现有审计模型。

### 3.2 未采用方案：每站一个专用爬虫

短期接入速度可能较快，但分页、重试、附件和生命周期逻辑会重复，后续官网变更需要同时维护大量实现，因此不采用。

### 3.3 未采用方案：所有来源统一使用浏览器自动化

浏览器只作为动态站点和验收工具。常规采集继续使用受限 HTTP 客户端，因为浏览器运行成本更高、失败面更大，也难以提供稳定的官方总数与末页证明。

## 4. 架构

### 4.1 多入口来源契约

一个逻辑来源可以配置多个 `listingEntries`。每个入口包含：

- 唯一入口代码；
- 官方列表 URI；
- 入口角色：`PRIMARY`、`HISTORICAL`、`SECTOR`、`LIFECYCLE` 或 `CAMPAIGN_STATE`；
- 分页模式及参数；
- 详情链接正则；
- 标题包含与排除规则；
- 适用年度；
- 是否为年度完整性所必需。

不同入口发现相同公告时，继续使用规范化官方 URL 和内容指纹去重。来源年度只有在所有必需入口均完成时才可形成完整性结论。

### 4.2 通用发现模式

系统支持以下发现模式：

1. `JCMS_PARAM_JSON`：浙江政务站点的 JCMS 列表与报告总数分页。
2. `STATIC_SUFFIX_TEMPLATE`：通过可配置模板生成 `list2.htm`、`News130a2.htm` 等静态页。
3. `LINKED_PAGE`：根据下一页链接遍历学校或医院列表。
4. `QUERY_PAGE`：通过 `?page=N` 等查询参数分页。
5. `JSON_API`：解析官方 JSON 列表的总页数、总数和详情标识。
6. `EMBEDDED_DATA`：解析官方 HTML 中内嵌的岗位数据对象。
7. `CAMPAIGN_STATE`：只监控当前招聘活动状态，不推断不存在的历史档案。
8. `FIXED_EVIDENCE`：只允许保存仍可访问、且明确标记为证据集而非当前增量入口的页面。

通用发现器必须检测总数突变、重复页、空中间页、末页不一致、超过配置上限和跨主机跳转。任何契约异常都不得静默写成零公告。

### 4.3 传输与安全边界

默认只允许 HTTPS。对于浙江工业大学和国科大杭州高等研究院这类官方站点仅提供 HTTP 的情况，使用显式的 `AUDITED_HTTP_READ_ONLY` 契约：

- 主机和路径前缀必须精确白名单；
- 只允许 `GET` 和 `HEAD`；
- 禁止发送 Cookie、Authorization、账号、表单数据和候选人信息；
- 禁止跟随到非白名单主机；
- 保存响应内容指纹和传输风险标记；
- HTTP 页面只作为公开官方证据，报名和登录仍交给用户浏览器。

附件下载主机逐来源配置。对象存储、招聘子域名或第三方承建系统必须先有官网跳转证据，不能使用全局通配白名单。

### 4.4 内容分类与用工性质

初始招聘和生命周期材料使用不同分类规则。`拟聘、成绩、资格复审、面试、体检、考察、递补、公示` 不得作为新岗位公告，但必须保留为生命周期材料。

岗位导入必须区分：

- 事业编制；
- 员额或备案制；
- 单位正式聘用；
- 国企正式劳动合同；
- 编外或项目聘用；
- 劳务派遣；
- 博士后或纯博士科研岗。

集团、医院多院区和高校附属单位必须保存实际用人主体，不能只记录发布公告的集团或主管单位。

### 4.5 完整性与失败语义

连接状态保留现有兼容语义，同时独立计算完成级别。`CONNECTED` 和有有效成功记录的 `PARTIAL` 仅能作为 Level 1 的候选证据；仍须核对真实运行及第二次复跑。`FAILED`、`NOT_CONNECTED` 不通过 Level 1。来源年度另用 `UNKNOWN / PARTIAL / ARCHIVE_UNAVAILABLE / MOVED / VERIFIED_NO_DATA / COMPLETE` 表达历史可得性和证明结论；404、筛选后零结果、单栏目空白均不足以支持无数据结论。

旧域名失效时，不再把死链接放入可抓取固定证据集。死链接可以作为带状态的历史来源证据保存，但不得导致每天重复抓取失败。

## 7. 测试策略

所有生产行为遵循 TDD：先写失败测试并验证预期失败，再实现最小代码。

### 7.1 契约测试

- 多入口去重和角色聚合；
- 必需入口未完成时禁止年度 `COMPLETE`；
- JCMS 报告总数、重复页和末页异常；
- UUID 与旧式文章 URL；
- 静态模板、查询参数、链接分页、JSON API 和内嵌数据；
- 审计型 HTTP 主机、路径、方法和跳转限制；
- 死固定证据不进入日常增量抓取。

### 7.2 解析测试

- 招聘公告与生命周期分类；
- 专业目录工作簿不导入岗位；
- 事业编、正式聘用、国企合同、编外和派遣识别；
- 集团子公司、医院院区和附属单位主体保存；
- 博士后、纯行政和明显不匹配类别排除。

### 7.3 真实验收

每个来源依次执行：

1. 增量运行；
2. 2024—2026 历史运行；
3. 再次增量运行；
4. 核对新增、更新、未变化、失败和下线数；
5. 浏览器检查来源页、年度证据、岗位详情和生命周期信息。

全量完成前运行完整 Maven 测试、前端类型检查和 Vitest，并对生产实例执行健康检查。

## 8. 可观测性与运维

来源页继续展示：

- 当前连接与访问状态；
- 最近成功/失败时间；
- 连续失败次数；
- 年度覆盖和完整性依据；
- 历史不可访问证据；
- 文档与附件问题；
- 生命周期匹配、待关联和歧义计数。

日常调度分散到不同时段，并尊重来源最小请求间隔。历史回填只手动执行或通过受控维护任务执行，不进入每天的增量调度。

## 9. 非目标

- 不自动登录报名系统。
- 不绕过验证码、访问控制或网站明确的反自动化限制。
- 不把第三方招聘汇总网站作为最终资格证据。
- 不因栏目中未发现目标岗位就推断该年度不存在岗位。
- 不在本批次扩展浙江以外地区，也不实现申请跟踪和备考任务管理。

## 10. 交付与版本控制

按三个来源批次分别提交，每批都在私有远程分支 `codex/phase4b-career-workbench` 保留可回滚节点。任何子 Agent 产出必须由主 Agent 检查差异并重新运行测试后才能提交。最终交付包含来源状态矩阵、真实运行编号、年度覆盖、岗位与生命周期计数、未能形成完整性结论的官方原因以及私有仓库提交记录。

## 11. 六级完成标准（替代旧总体完成口径）

验收对象包含注册表快照、来源、年份和采集截止时刻。2026 是截至运行日的年内覆盖，不能证明尚未发生的全年招聘。每级保存 `PASS / FAIL / UNKNOWN`、证据引用、评估时间和阻塞项；最高连续通过级别才是 source 的 `completionLevel`，未知不能算通过。官方明确不适用的阶段须保存不适用依据。

| 级别 | 通过条件 | 不能作为充分证据的情况 |
| --- | --- | --- |
| Level 1 Connectivity Complete | 全部规划来源真实运行，当前无 FAILED/NOT_CONNECTED；第二次同窗口复跑无重复新增，变化有解释；入口身份经过核验 | 可访问首页、旧绿色状态、全部失败却标记部分成功 |
| Level 2 Historical Coverage Complete | 2024/2025/2026 各年必需栏目、时间范围、官方可得档案、页数和数量对账均有证据；站内搜索/年度索引/主管渠道核验；无未解释的重大历史缺口 | 仅遍历末页、目标岗位数量大于零、筛选后零公告 |
| Level 3 Document Complete | 招聘正文及重要附件有可回放快照；每个重要附件已处理或保存明确失败及复核处置；发现数量与清单对账 | 未下载附件不计入分母、扫描件当零岗位、忽略名单表 |
| Level 4 Lifecycle Complete | 批次统一关联各阶段与变更；未关联/歧义材料全部列明原因和处置；每批已知缺失阶段可查询 | 按不同 URL 建多个批次、缺阶段静默消失 |
| Level 5 Opportunity Complete | 批次级稳定岗位身份、不可变版本、性质/资格/报名事实及来源证据齐备；影响资格或岗位身份的 unresolved 项已处理 | 直接覆盖历史、用报名截止日猜年龄基准、未知条件默认满足 |
| Level 6 Audit Complete | 跨官方验证渠道对账，无未解释的重大 coverage gap；所有 warning 有证据处置；审计可复现 | source 全绿、无验证源、分母未知却报告 100% |

Level 3 允许明确失败原因存档，代表文档账目闭合，不代表解析成功率 100%；重要岗位表的未解决解析失败仍阻止 Level 5，造成重大未知机会则阻止 Level 6。某年份真实档案无法获得时可记录 `ARCHIVE_UNAVAILABLE` 并说明可得范围，但不能宣称该年度机会已穷尽。`VERIFIED_NO_DATA` 必须有官方负面证据与独立渠道核验；不存在证据时使用 `UNKNOWN/PARTIAL`。

## 12. 十八项要求的模型与实现边界

完整基线审计见 [2026-09-07 审计](../../audits/2026-09-07-remote-local-acquisition-audit.md)。该表逐项列出现有文件、已具备能力、缺口及实施阶段，不能把设计目标当作已实现能力。

### 12.1 来源、渠道与招聘批次（要求 1—4、17）

沿用 `recruitment_source`、多 `listingEntries` 和 `recruitment_event`，补充每单位栏目清单及审计日期。登记招聘、校招、社招、高层次、人事、考试、复审、笔试、面试、体检、考察、递补、公示等栏目是否存在及官方证明。验证源使用独立角色，不重复创建岗位；相同事件仅见于验证源时产生 gap。

批次建立官方编号/单位/年度/批次名的规范身份和多来源证据关联。合并优先使用明确官方编号与原文引用，标题相似只能产生候选；歧义保留人工复核。岗位键首选 `batch + employer + job_code`；无代码使用 `batch + employer + title + key_qualifications`。条件更正导致后备键变化时，通过批次内身份候选和官方更正引用关联原岗位，不能直接生成重复新岗。保留旧 URL 键 alias 和原证据，迁移不丢失用户核实记录。

### 12.2 版本、性质与生命周期（要求 5、6、12、13）

沿用现有 `EmploymentType`，增加独立招聘类型，逐岗位保存实际用人单位和原文，不能由单位性质推断岗位正式性。现有岗位表保存当前投影；新增不可变岗位版本及有来源的变更事件，存 before/after、有效时间、发现时间、原始文档。

统一阶段为 announcement、registration、qualification、written_exam、interview、physical_exam、investigation、offer/publication；附加 correction、cancellation、reduction、extension、replacement、abandonment。人数、核减、取消、补报名、条件更正、复审/体检递补、放弃及拟聘都有事件，不覆盖历史。报名事实包括 URL、渠道、开始/结束时刻、复审时间、考试时间、账号要求。延期事件保留原 deadline。名单文档保留分类和关联，按必要性脱敏展示。

### 12.3 附件、失败和原始证据（要求 7—9）

复用 `acquired_document`、`source_artifact`、`extraction_run`、`review_item` 和导入失败记录，增加持久化文档清单：document_type、source_url、raw_checksum、parser_status、extraction_status、extraction_confidence。内容指纹与原始字节校验和分别保存，网页去除动态时间不改变 raw checksum。

文档类型覆盖岗位表、专业目录、报名表、成绩、面试/体检/公示名单和其他；支持 xls/xlsx/doc/docx/pdf/zip。ZIP 子文档保留父子来源并限制解包规模与路径。图片/扫描/不支持/下载失败/解析失败明确为 IMAGE_ONLY、SCANNED、NEEDS_REVIEW、DOWNLOAD_FAILED、PARSE_FAILED 或兼容映射；进入复核队列，绝不作为零岗位。重要 HTML、JSON API、列表页和附件快照均绑定 URL、抓取时间和 hash。

### 12.4 资格与政策（要求 14、15）

复用公告事实融合和字段级证据，覆盖学历、学位、专业、年龄、应届年份、境外学历、留服、工作经历、社保、未落实工作单位、户籍、职称、证书、政治面貌和特殊要求。正文、补充公告和复审通知都可贡献规则；冲突必须显示，不静默覆盖。2027 毕业生资格只能由适用年度/地区/对象的官方规则确定。

复用现有 `policy_rule`，增加 `policy_source`、政策版本及 `policy_rule → applicable_job/recruitment` 关系。规则保存生效期限、适用范围、官方原文及证据位置。政策源与招聘 source 分开统计；应届、境外、留服、社保、未就业、年龄和专业目录均有覆盖矩阵。parser 只抽取原文事实，不硬编码未知政策结论。

### 12.5 覆盖证明和反漏采（要求 10、11、16、18）

每个 source-year-entry 保存时间范围、页数、全部公告与招聘公告数、岗位数、附件数/成功率、生命周期数、未关联数、解析失败数、最早/最晚日期、最近成功时间、终止原因及交叉验证证据。计数按当前有效文档版本去重，失败重试不能重复计入失败分母；缺失数量为 unknown，不能显示为零。

审计仪表盘展示连接状态、年度覆盖、正文/岗位/附件、parser failure、lifecycle linkage rate、orphan、unresolved jobs/events、last success、幂等状态、coverage confidence、gap 和 verification warnings。confidence 是证据满足程度的透明规则结果，不能伪装成全市场召回率。

最终报告必须包含实际规划来源数和名单快照、CONNECTED/PARTIAL/FAILED/NOT_CONNECTED、逐年覆盖分子/分母和未知数、招聘事件数、去重岗位数、生命周期事件数、附件成功/失败、orphan/unresolved、policy coverage、gap、verification warnings、每个来源完成级别及无法证明完整的原因。不同粒度的来源、入口、批次、文档不能混作分母。
