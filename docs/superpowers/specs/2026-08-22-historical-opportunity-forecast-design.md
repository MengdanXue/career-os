# 2024–2026 历史机会研究与 2027 求职预测设计

**状态：** 已批准  
**数据年度：** 2024、2025、2026  
**预测年度：** 2027  
**首位候选人：** 计算机相关本科 + 境外硕士在读的示例画像（具体字段见种子数据，均为虚构占位）  
**目标：** 将 Career OS 从实时采集与审核后台，调整为能够回答“过去三年有什么规律、目标年度可能有什么机会、这位候选人能不能报、什么时候考试、现在该准备什么”的职业研究与行动系统。

## 0. 设计方法与取舍

本设计吸收以下开源 Skill 的成熟方法，但不把它们作为生产运行依赖：

- [**Data Liberation**](https://github.com/CUPIDS-Lab/data-liberation-skill)：采用“调查 → 提取 → 整理 → 审计”的可重放政府数据管线、不可变原件、来源清单、数据字典和跨年度概念映射；
- [**Analyze Data Quality**](https://github.com/openai/role-specific-plugins/blob/main/plugins/data-analytics/skills/analyze-data-quality/SKILL.md)：在解释历史规律前检查完整性、唯一性、有效性、一致性、完整引用、时效性和数据形状，并按年度与来源展示比率；
- [**Reference Class Forecasting**](https://github.com/lyndonkl/claude/blob/main/skills/reference-class-forecasting/SKILL.md)：先定义可比历史样本，再做外部基准判断；样本过少时扩大参考类或明确不确定性，不用故事替代频率；
- [**Design KPIs**](https://github.com/openai/role-specific-plugins/blob/main/plugins/data-analytics/skills/design-kpis/SKILL.md) / [**Dashboard Building**](https://github.com/openai/role-specific-plugins/blob/main/plugins/data-analytics/skills/build-dashboard/SKILL.md) / [**Data Visualization**](https://github.com/openai/plugins/blob/main/plugins/build-web-data-visualization/skills/data-visualization/SKILL.md)：首页围绕用户决策组织，采用“结论 → 趋势 → 原因 → 明细 → 行动”的阅读路径，图表必须可下钻到原始岗位与官方证据；
- [**Scribe**](https://github.com/simota/agent-skills/blob/main/scribe/SKILL.md)：核心需求使用稳定 ID、二元可验收条件和 Given-When-Then 场景，形成需求、实现和测试之间的追踪关系。

明确不采用：

- 不安装或引入 [TimesFM Forecasting](https://github.com/google-research/timesfm/blob/master/timesfm-forecasting/SKILL.md) 等时序基础模型。单位 × 岗位族在三年内通常只有 0–3 个年度观测，且招聘属于稀疏事件，不满足可信概率预测所需的连续时序条件；
- 不安装只有通用浏览器动作、没有来源清单、版本、审计和证据模型的“万能爬虫 Skill”；
- 不把第三方招聘聚合站的数量当作官方数据覆盖率分母。

以上 Skill 当前只作为设计与验收方法使用，不复制其运行时代码，避免引入 Python 脚手架、跨仓库引用或与现有 Java 架构重复的依赖。

## 1. 问题定义

当前系统已经能够采集浙江省人社厅和杭州市人社局公告、下载官方附件、解析 Excel 岗位并保留证据，但产品闭环尚未成立：

- 岗位库、已核验岗位、候选人匹配和可信机会使用不同口径，用户同时看到“数千条记录”“12 个匹配”和“0 个可信机会”；
- 历史数据没有按招聘年度组织，无法比较单位复招、要求变化、招聘月份和考试方式；
- 当前候选人仍是单一最高学历的 Seed Profile，无法表达本科与预计毕业的境外硕士两段教育经历；
- 抽取模型不可用时，人工审核队列出现“置信度 0%、0 个岗位”的不可操作任务；
- 决策助手只读取空的可信机会池，无法利用已有的候选人匹配与历史岗位回答问题；
- 页面优先呈现采集状态和技术证据，而不是求职者需要的机会、时间、资格、考试和行动。

本阶段不以扩大实时抓取数量为首要目标，而以形成可靠的三年历史样本和可解释的 2027 行动建议为目标。

## 2. 产品结果

系统必须能够稳定回答以下问题：

1. 2024–2026 年浙江、重点杭州出现过哪些稳定计算机技术岗位？
2. 哪些单位或岗位族连续招聘、隔年招聘或只出现一次？
3. 公告、报名、笔试和面试通常集中在哪些月份？
4. 哪些岗位有笔试，考什么；哪些有专业测试或只有面试？
5. 年龄、学历、专业、应届、境外学历、工作经历和职称要求如何变化？
6. 根据历史证据，2027 年哪些时间窗口、单位和岗位族值得重点监控？
7. 结合候选人画像，哪些岗位可报、条件可满足、需要确认或明确不符合？
8. 用户现在应准备哪些材料、考试内容和时间提醒？

## 3. 产品边界

### 3.1 本阶段包含

- 2024、2025、2026 三个招聘年度的官方公告与岗位附件；
- 浙江全省，杭州优先；
- 事业单位、政府直属信息中心、医院信息中心、高校正式信息化岗位、科研院所工程技术岗位以及有正式用工证据的政府背景技术岗位；
- 计算机、软件、数据、人工智能、网络安全、信息化、信息系统和数字政府相关岗位；
- 历史时间、资格、考试方式、用工性质和单位复招规律；
- 基于历史频率与时间分布的 2027 预测；
- 候选人资格判断、条件缺口与备考行动。

### 3.2 本阶段不包含

- 自动报名或自动提交个人信息；
- 没有历史样本支持的录取概率；
- 对未发布的 2027 具体日期作确定性承诺；
- 用“看起来像事业单位”推断事业编制；
- 全国范围招聘扩张；
- 复杂机器学习预测模型；
- 在缺少模型配置时生成伪 Agent 结果。

## 4. 正式候选人画像

### 4.1 已确认事实

- 性别：女；
- 出生：1992 年 12 月，具体日期未知；
- 本科：计算机科学与技术，2014 年毕业；
- 硕士：示例海外大学，计算机科学专业，预计 2027 年毕业；
- 工程背景：Java 后端、企业级软件开发、数据库、信息系统；
- 研究背景：人工智能、图神经网络、机器学习实验；
- 职称：中级计算机应用，通过评审取得；
- 地点优先级：杭州第一，浙江其次，江苏、广东、福建为扩展地区；
- 目标：事业单位专业技术岗、政府信息与数据中心、数字政府、科研院所工程技术、高校正式信息化、医院信息中心、政府背景国企正式技术岗；
- 排除：劳务派遣、短期项目制、纯行政、纯销售、博士限定科研岗、高校纯教师岗。

### 4.2 待确认事实

- 具体出生日期；
- 示例海外大学预计毕业月份、学位取得时间和留服认证计划；
- 工作经历年限与可提供的合同、社保等证明；
- 2027 年报考时的在职、社保和应届身份；
- 可作为资格或竞争证据的项目、论文、证书与技能材料。

待确认事实不得被转成否定事实。遇到年龄截止日接近 9 月、应届定义依赖学位取得日期或经历证明不足时，资格结果必须是 `UNCERTAIN`，并明确告诉用户需要补充什么。

### 4.3 画像模型

候选人从单一 `highestEducation + graduationYear` 升级为可重复的 `EducationRecord`：

- `institution_name`
- `country_or_region`
- `education_level`
- `major_name`
- `graduation_year`
- `graduation_month`
- `completion_status`：`COMPLETED`、`EXPECTED`
- `credential_verification_status`：`NOT_REQUIRED`、`PLANNED`、`IN_PROGRESS`、`VERIFIED`、`UNKNOWN`

保留候选人主专业、技能、研究方向、职称、地点和用工偏好作为独立事实。每项事实保留确认状态与确认时间。

## 5. 历史数据模型

### 5.1 RecruitmentEvent

一个招聘事件代表一份公告及其公共流程，至少包含：

- 招聘年度、公告标题、发布单位、发布日期；
- 报名开始与截止、资格审查、缴费、准考证、笔试、面试相关时间；
- 报名入口；
- 笔试科目、面试方式、专业测试；
- 应届生范围、境外学历、工作经历证明和聘用规则；
- 官方公告链接、附件集合、内容指纹和抓取时间。

### 5.2 JobPosting

一个岗位代表附件中的一行或公告中独立的岗位，至少包含：

- 单位、主管部门、岗位名称、岗位代码、招聘人数；
- 岗位族、岗位类别、岗位等级、工作地点；
- 学历、学位、专业、年龄、性别、应届、经历、职称和其他条件；
- 是否笔试、笔试科目、是否专业测试、面试入围比例；
- 用工性质与对应证据；
- 招聘年度与招聘事件关联；
- 稳定岗位键、内容指纹、有效状态与字段级证据。

### 5.3 历史分析读模型

新增只读分析结果，不污染官方事实：

- `OrganizationYearPresence`：单位在每个年度是否招聘目标岗位；
- `JobFamilyYearPresence`：单位与岗位族在每个年度的岗位数量；
- `RecruitmentWindow`：公告、报名、笔试、面试的月份与间隔；
- `RequirementTrend`：年龄、学历、专业、应届、经历、职称要求的年度变化；
- `ExamPattern`：笔试、科目、专业测试和面试方式的历史分布；
- `CandidateHistoricalFit`：候选人在历史公告当年的可报状态和原因；
- `ForecastSignal`：2027 时间窗口、单位、岗位族、证据强度及支撑证据。

分析结果可重新计算，不作为官方事实来源。

### 5.4 历史数据集契约

历史研究的最小观察粒度必须固定：

- 公共招聘流程以 `RecruitmentEvent` 为一条观察；
- 岗位要求以 `JobPosting` 为一条观察；
- 跨年复招以“规范单位 × 规范岗位族 × 招聘年度”为一条观察；
- 时间窗口以已明确日期的事件为一条观察，只有月份而无日期时不得伪造日级精度。

每次发现、下载、解析和回填运行必须生成 `AcquisitionRun`，记录 `run_id`、来源、年度、开始/结束时间、代码版本、解析器版本、成功/失败数量与失败原因。每份原始文档生成 `SourceArtifact`，至少包含：

- 原始 URL、规范 URL、发现页 URL；
- 获取时间、HTTP 状态、文件名、MIME 类型和字节数；
- SHA-256 内容哈希、公告/附件关系、招聘年度；
- 解析器与模式版本、可访问状态、归档状态；
- 是否参与当前分析以及被排除的原因。

已下载原件不可原地修改。来源更新产生新版本，以内容哈希和抓取时间区分；清洗、映射和解释只作用于派生数据。

跨年度字段采用概念目录而不是简单改名。单位、岗位族、专业、考试方式和用工性质的映射必须同时保存：来源原值、规范值、适用年份、映射依据、不可比较的限制。无法确认等价时保留不同概念，不强行合并。

### 5.5 覆盖账本与数据质量门

每个“配置来源 × 招聘年度”维护 `SourceYearCoverage`，状态为：

- `NOT_DISCOVERED`：尚未完成年度入口发现；
- `DISCOVERED_NOT_FETCHED`：已发现但尚未下载；
- `ACCESS_FAILED`：访问失败；
- `FETCHED_NOT_PARSED`：已下载但尚未结构化；
- `PARTIAL`：只完成部分公告或附件；
- `COMPLETE`：按该来源可验证的年度索引完成发现、下载与解析；
- `NO_TARGET_RECORDS`：已完成发现，但没有目标技术岗位。

只有 `COMPLETE` 或 `NO_TARGET_RECORDS` 才能支持“该来源当年无目标岗位”的结论。页面上的年度覆盖率分母是已配置且有明确年度入口的来源，不是搜索引擎结果数，也不是第三方网站记录数。

分析前执行并展示以下质量门。质量门按“来源年度/参考类/岗位”的相应粒度计算：聚合切片未达门槛时阻断趋势结论；单个岗位若自身关键字段证据完整，仍可给出该岗位的确定性资格结果。

| 质量维度 | 指标 | 第一阶段门槛 | 未通过的产品行为 |
|---|---|---:|---|
| 完整性 | 关键字段证据覆盖率 | `>= 80%` | 只显示描述统计，不给确定资格结论 |
| 唯一性 | 活跃稳定岗位键重复率 | `0%` | 阻断趋势与 Top 20 重算 |
| 有效性 | 日期、人数、年龄、枚举规则错误率 | `0%`（硬规则） | 错误记录进入 reject port，不参与分析 |
| 一致性 | 公告与附件关键字段未解决冲突率 | 单独展示 | 对应结论降为 `UNCERTAIN` |
| 完整引用 | 岗位 → 附件/公告可追溯率 | `>= 95%` | 无引用记录不得支撑预测 |
| 年度覆盖 | `COMPLETE/NO_TARGET_RECORDS` 来源占比 | 页面可见 | 不把缺口解释为零招聘 |
| 形状稳定 | 年度/来源记录量与字段缺失率异常 | 人工确认后放行 | 标记结构变化并暂停该来源聚合 |

所有指标同时显示数量、比率、分母、年度、来源范围和计算时间。系统不得只显示“采集了 2,406 条”而隐藏其中可用于决策的比例。

## 6. 数据获取与回填

### 6.1 数据源优先级

1. 浙江省人力资源和社会保障厅；
2. 杭州市人力资源和社会保障局；
3. 杭州重点区县政府与人社部门；
4. 重点高校、医院、科研院所和政府直属单位官网；
5. 政府背景国企官网，仅纳入能确认正式用工的岗位。

第三方招聘网站只用于发现线索，不作为最终资格证据。

历史官网页面失效时，可使用政府网站历史库、官方转载页或 Internet Archive 定位原文，但必须标记 `ARCHIVED_COPY`、归档时间与原官方域名；只有能确认内容来自官方发布的归档副本才可作为辅助证据，第三方转述不能替代岗位附件。

### 6.2 年度回填流程

```text
年度入口与站内搜索发现
  → 公告归档
  → 官方附件下载
  → 公告公共规则解析
  → Excel/PDF 岗位结构化
  → 稳定岗位键与内容指纹
  → 字段级证据
  → 候选人历史资格判断
  → 年度聚合
  → 2027 预测信号
```

2024、2025、2026 使用相同解析和证据标准。历史附件失效时，保留已获取文件的内容哈希、原始 URL 和抓取记录，并将可访问性与事实可信度分开表示。

回填不是一次“大爬取”，而是可审计的分批发布：

1. **Survey**：为每个来源记录年度入口、公告粒度、附件类型、翻页方式、结构变化、官方总数或可核对索引；
2. **Discover**：形成来源清单和待获取文档清单，保存“为何认为发现已完成”的依据；
3. **Fetch**：保存不可变原件、响应元数据和内容哈希；
4. **Parse and Normalize**：按来源和年份选择解析器，保留原值、规范值与字段级证据；
5. **Reject Port**：格式损坏、字段越界、无法归属的行持久化为可重试记录，不静默丢弃，也不让单行失败终止整批；
6. **Audit and Reconcile**：核对公告所述招聘人数、附件岗位数、解析行数、入库数、拒绝数和重复数；
7. **Publish**：只有通过数据质量门的批次才进入历史分析读模型，批次撤回后可从原件与版本重放。

每个来源至少保留一个真实年度解析样本作为回归夹具；来源结构改变必须新增版本分支和测试，不能修改旧解析结果来“适配现在”。

### 6.3 审核原则

- 只把影响候选人资格、用工性质、考试方式和预测规律的冲突送入人工复核；
- 已由 Excel 明确提供的岗位不得因为公告 LLM 抽取失败而回退成“0 个岗位”；
- `MODEL_UNAVAILABLE` 是系统运行错误，不是用户可审核的业务任务；
- 空提案不能执行“确认并入库”；
- 审核按字段或冲突分组，不要求用户重新录入整份公告。

## 7. 资格判断

资格引擎对每个历史或未来岗位输出：

- `ELIGIBLE`：已确认事实满足全部硬条件；
- `CONDITIONALLY_ELIGIBLE`：预计毕业、留服认证或材料在截止前完成即可满足；
- `UNCERTAIN`：缺少具体出生日期、毕业月份、经历证明等关键事实；
- `INELIGIBLE`：有明确硬条件不符；
- `NOT_TARGET`：岗位不属于目标技术与稳定用工范围。

规则引擎负责年龄、学历、专业、毕业年份、经历、职称和性别等确定性判断。LLM 只解析规则原文与生成解释，不覆盖规则结果。

对于 2027 年预测岗位，在正式公告发布前只输出“历史上通常要求”和“需要提前准备”，不得提前给出确定的 `ELIGIBLE`。

## 8. 2027 预测方法

第一版使用透明的统计与规则信号，不使用黑盒预测。所有结果携带 `as_of_date`、训练年度范围、算法版本、参考类、样本数和证据岗位 ID，保证同一快照可以重复计算。

### 8.0 参考类层级与最小样本约束

系统按从具体到宽泛的顺序选择参考类：

1. 同一规范单位 × 同一岗位族；
2. 同一规范单位 × 上级岗位族；
3. 同一机构类型 × 同一城市 × 同一岗位族；
4. 同一机构类型 × 浙江省 × 同一岗位族。

每次放宽参考类都必须在界面上说明，不得把“浙江医院信息岗位的规律”写成“某家医院必然招聘”。参考类还必须通过同质性、时间相关性和机构/政策结构变化检查。

样本门控：

- `N < 3`：只列历史事实，不生成时间窗口或趋势等级；
- `3 <= N < 5`：允许显示“观察信号”，不得输出概率、百分比或高置信度；
- `5 <= N < 20`：允许输出低/中证据强度的月份区间和要求分布；
- `N >= 20` 且回测通过：未来才允许引入经过校准的概率或区间覆盖率，本阶段仍不展示录取概率。

这里的 `N` 是参考类内独立招聘事件数，不是岗位行数。同一公告的 100 个岗位不能伪装成 100 次独立复招观测。

### 8.1 单位复招信号

- 三年均出现同一目标岗位族：标为“连续三年出现”，不是统计上的高概率；
- 三年中出现两年：标为“两年出现”，并列出缺失年覆盖状态；
- 只出现一年：标为“单年观察”，不得据此承诺 2027；
- 同一单位名称变更或机构合并需有明确映射证据。

### 8.2 时间窗口信号

- 使用历史公告、报名、笔试和面试日期的月份分布；
- 输出最常见月份范围、样本事件数、年份数和离散程度；
- 不完整日期不参与日级间隔计算；
- 样本门控不满足时只展示历史月份点，不合成为预测窗口；
- 2027 具体日期在公告发布前显示为预测窗口，不显示为截止日期。

### 8.3 要求趋势信号

- 比较同一单位与岗位族三年的学历、年龄、应届、经历和职称要求；
- 区分稳定要求、趋严、趋宽和样本不足；
- 所有趋势必须列出对应年份和原始岗位。

### 8.4 机会优先级

2027 关注优先级由以下维度组成：

- 历史复招强度；
- 目标岗位族匹配；
- 历史资格可满足程度；
- 用工稳定性证据；
- 地点优先级；
- 考试准备复用度；
- 证据覆盖和样本数量。

分数是机会决策指数，不是录取概率。每个分项必须可解释。

### 8.5 回测、时间切分与结构变化

预测信号上线前执行滚动历史回测：

- 仅用 2024 数据生成对 2025 的观察清单；
- 仅用 2024–2025 数据生成对 2026 的观察清单；
- 严禁使用预测截止日之后才获取、修正或发布的字段，避免时间穿越；
- 分别记录单位/岗位族命中率、Top-K 召回率、预测窗口命中率和无法评估的覆盖缺口；
- 回测结果按参考类、地区、机构类型和岗位族分层，不能只报一个总体平均值。

政策变化、机构合并、招聘制度变化、来源入口迁移或连续年度覆盖异常触发 `STRUCTURAL_BREAK`。该标志暂停沿用旧趋势，页面展示变化原因，并要求用户把信号当作历史参考而非 2027 预测。

任何未来引入的统计模型必须先与“去年是否出现”“三年出现次数”“月份中位数”等简单基线比较；不能稳定优于基线就不得替换透明规则。

## 9. Agent 设计

### 9.1 Historical Recruitment Analysis Agent

输入候选人、时间范围和问题，使用结构化历史数据回答：

- 哪些单位连续招聘；
- 哪些月份需要关注；
- 哪些岗位族最常出现；
- 要求和考试方式如何变化；
- 结论由哪些年份和公告支撑。

### 9.2 Eligibility and Action Agent

基于候选人事实、岗位规则和时间窗口回答：

- 当前是否具备资格；
- 哪些条件预计可在 2027 年满足；
- 还缺哪些事实或材料；
- 何时准备留服认证、报名材料和考试；
- 建议的下一步行动。

### 9.3 运行约束

- Agent 只读取可引用的结构化事实和证据；
- 返回 Typed DTO，并为结论附证据 ID；
- 无模型配置时明确显示 Agent 不可用，同时保留确定性分析结果；
- 不得用“可信池为空”覆盖已有的候选人历史匹配；
- 不得把预测窗口表述成确定公告日期；
- 不执行自动报名。

### 9.4 Agent 工具契约与工作流

Agent 是解释和行动编排层，不直接承担抓取、Excel 解析、稳定键、资格计算或统计聚合。它只调用以下有界工具：

- `SearchHistoricalOpportunities`：按年份、地区、机构类型、岗位族和资格状态返回分页历史岗位；
- `GetRecruitmentPatterns`：返回参考类、覆盖状态、复招、月份、要求和考试聚合；
- `EvaluateCandidateEligibility`：使用画像版本、资格规则版本和 `as_of_date` 返回确定性结果；
- `GetOfficialEvidence`：按事实/岗位 ID 返回公告、附件、定位和原文摘录；
- `GetForecastSignals`：返回已经回测并通过样本门控的 2027 信号；
- `BuildCandidateActionPlan`：把已确认的截止、预计窗口、材料缺口和考试模式转成行动项草案。

标准回答流程：

```text
用户问题
  → 意图与筛选条件解析
  → 调用结构化查询/规则/聚合工具
  → 证据完整性与样本门控检查
  → 生成候选人可读解释
  → 引用校验器确认每个关键结论有 evidence_id
  → Typed DTO 与可下钻链接
```

Agent 不获得无限制 SQL，也不在回答阶段临时浏览第三方网站补齐关键资格事实。工具失败时返回明确错误和已成功的部分结果；引用校验失败时删除无证结论，而不是让模型自行补写。

## 10. 用户界面

### 10.1 我的 2027 机会

首页直接呈现：

- 下一个预计招聘窗口及倒计时；
- 2027 重点关注单位与岗位族；
- 近三年重复招聘证据；
- 当前资格优势、条件缺口与材料准备；
- 本月、本季度和公告发布后的行动清单。

首页不得以采集记录数、数据库状态或空的 T1/T2/T3 为主要信息。

首页默认阅读路径固定为：

1. **现在的结论**：下一个关注窗口、可准备机会数、最重要的一个条件缺口；
2. **为什么**：近三年复招与月份分布，直接显示样本数和覆盖状态；
3. **与你的关系**：明确可满足、预计可满足、待确认和不符合；
4. **接下来做什么**：按日期排列的材料、复习和监控动作；
5. **查看原始依据**：下钻到历史岗位、公告、附件和字段证据。

默认视图无需操作即可回答核心问题。筛选器只保留地区、机构类型、岗位族、年份和资格状态；筛选、年份范围、排序与选中对比项写入 URL，刷新、返回和复制链接后状态一致。

### 10.2 三年历史岗位库

提供年份、地区、单位、岗位族、学历、年龄、应届、境外学历、笔试、专业测试和用工性质筛选；支持按公告时间、匹配程度、单位复招次数排序，并支持跨年度比较。

岗位列表优先显示：单位、岗位、年份、是否历史可报、学历/年龄、是否笔试、报名与考试时间。技术证据不在列表中展开。

### 10.3 招聘规律

- 年度与月份时间线；
- 公告、报名、笔试、面试月份热力图；
- 连续招聘单位与岗位族；
- 要求变化矩阵；
- 笔试科目、专业测试和面试方式统计；
- 每个图表可回到构成它的历史岗位。

图表采用最简单且可核验的表达：月份使用年度小倍数或热力图，复招使用单位 × 年份矩阵，要求变化使用带原文入口的变化表。不得用 3D、装饰性动画或只在悬停时才出现的关键信息。缺失、部分覆盖和真实零值使用不同视觉状态。

桌面与手机是同级设计。移动端按“结论 → 依据 → 行动”重排，关键值无需 hover，图表提供表格替代、键盘/触摸路径、足够对比度与非颜色编码。

### 10.4 备考与行动

- 预计关注窗口；
- 报名材料清单；
- 留服认证与毕业材料节点；
- 常见笔试科目与复习计划；
- 专业测试和面试准备；
- 关注、准备中、已报名、已考试、已结束状态管理。

### 10.5 岗位详情

默认只展示：

1. 历史当年能否报名及原因；
2. 公告、报名和考试时间；
3. 是否笔试、考什么、是否专业测试；
4. 全部报考要求；
5. 用工性质；
6. 对 2027 准备的参考意义；
7. 官方公告与附件。

字段英文名、JSON locator、内容指纹和解析版本放入折叠的“高级证据”区域。

所有远程数据视图显示 `最后计算时间`、`数据截至日期` 与 `完整/部分/离线` 状态。刷新失败时保留上次可用结果并标记为陈旧，不以空白页或全零代替。

### 10.6 数据管理后台

官方来源运行、手工导入、迁移状态、模型错误和技术审核从主要导航移入数据管理区域。普通用户不需要理解数据准入状态机。

## 11. 状态口径

系统分别维护但不混淆：

- 数据是否成功采集；
- 岗位是否成功结构化；
- 关键字段是否有证据；
- 是否属于目标岗位；
- 候选人历史资格状态；
- 是否值得在 2027 关注；
- 用户行动状态。

页面中的总数必须注明统计口径和年度范围。历史分析不得被“可信机会准入”完全阻断；未知或有冲突的事实可以参与样本计数，但不得支持确定性资格结论。

## 12. 失败与降级

- 单个公告或附件失败不阻断同一来源其他文档；
- 官方链接失效时显示已归档证据和失效状态；
- LLM 不可用时继续完成 Excel 解析、规则判断、历史聚合和统计预测；
- 样本不足时输出“样本不足”，不输出百分比概率；
- 候选人事实缺失时输出待补事实与影响范围；
- 历史数据尚未补齐时，页面显示年度覆盖率，不把缺失年度解释为“当年没有招聘”。

### 12.1 产品成功指标

第一阶段只维护少量能改变决策的指标：

| 角色 | 指标 | 定义 | 目标/护栏 |
|---|---|---|---|
| Primary KPI | 决策就绪岗位率 | 完整来源年度中，目标岗位里关键资格、流程、用工性质与官方引用足以支持下一步行动的岗位数 / 目标岗位数 | `>= 80%` |
| Primary KPI | 三年核心来源完成率 | A 级配置来源中，2024–2026 达到 `COMPLETE` 或 `NO_TARGET_RECORDS` 的来源年度数 / 应完成来源年度数 | 首次发布 `>= 90%` |
| Primary KPI | 核心问题任务成功率 | 真实候选人无需进入数据管理即可找到“何时、什么岗位、能否报、考什么、现在做什么”的验收任务通过数 / 总任务数 | `100%` |
| Driver | 关键字段证据覆盖率 | 决策关键字段中有明确官方证据或明确 `NOT_REQUIRED` 的字段数 / 应有字段数 | `>= 80%` |
| Driver | 从公告发布到候选人可见的延迟 | 当前年度官方公告发布时间到可在候选人视图查看的时间 | 中位数 `<= 6h`，P95 `<= 24h` |
| Guardrail | Golden Dataset 假可报率 | 实际硬条件不符却被判为 `ELIGIBLE` 的岗位数 / 人工标注不符合数 | `0%` |
| Guardrail | 活跃重复岗位率 | 相同稳定岗位键同时活跃的记录数 / 活跃岗位数 | `0%` |
| Guardrail | 无证预测率 | 没有样本数、参考类、历史岗位与截至日期的预测信号数 / 全部预测信号数 | `0%` |

指标必须固定分子、分母、来源范围、计算版本和时间窗口。目标值在第一轮真实回填后以基线复核，但不得通过缩小分母、隐藏失败来源或把未知改成满足来“达标”。

### 12.2 非功能约束

- **可重放**：相同原件、映射版本和解析器版本重跑，稳定键、事实和聚合结果一致；
- **幂等**：同一批次重复执行不新增重复事件、岗位或证据；
- **可追溯**：任何首页结论最多两次下钻可到官方公告或附件；
- **性能**：在 30 个来源、3 个年度和 10,000 个岗位规模下，历史列表/聚合 API 热缓存 P95 `<= 800ms`，首页主要内容本地网络 P95 `<= 2s`；
- **降级**：模型、单一来源或刷新任务失败不清空已有结果，必须显示陈旧或部分状态；
- **隐私**：候选人出生、教育、经历和材料状态默认仅本地/私有环境可见，不写入日志、来源证据或公开导出；
- **版本化**：资格规则、映射、聚合和预测均有版本与 `as_of_date`，旧结果可解释；
- **可访问性**：核心流程可用键盘完成，状态不只依赖颜色，关键图表有文本/表格替代。

## 13. 实施顺序

1. 正式候选人教育经历与已确认事实；
2. 统一历史年度、时间、考试和要求字段；
3. 建立来源注册表、年度覆盖账本、不可变原件、运行清单和 reject port；
4. 选择三类真实公告/附件完成可重放的纵向切片，并通过对账与质量门；
5. 分批完成 2024、2025 数据发现与回填，2026 按同一合同重放；
6. 历史资格读模型和筛选查询；
7. 单位复招、时间窗口、要求趋势与考试模式聚合；
8. 先实现简单基线和滚动回测，再发布 2027 透明预测信号；
9. 按“结论 → 依据 → 行动”重做“我的 2027 机会”和历史岗位库；
10. 招聘规律、图表下钻与备考行动；
11. 接通两个 Agent，并完成证据引用与无模型降级；
12. 真实用户验收、可访问性检查、性能验证和数据质量抽样。

后续实现计划和测试名称必须引用至少一个需求 ID；需求改变时同步更新本表和对应测试，避免设计、代码与验收各自使用不同口径。

### 14.1 数据

- 2024、2025、2026 三个招聘年度均可检索；
- 至少 30 个重点单位；
- 至少 200 个目标技术岗位；
- 至少 95% 的纳入岗位可追溯到官方公告、附件或明确标记的官方归档副本；
- 至少 80% 的纳入岗位达到关键字段证据覆盖门槛；
- 页面显示各年度覆盖率，不将采集缺口解释为零招聘；
- 同一岗位重复运行不产生重复历史记录。

### 14.2 资格与历史分析

- 年龄、学历、专业、性别、应届、境外学历、经历和职称均有规则结果；
- 具体出生日期未知时，临界年龄结论不会被误判为可报或不可报；
- 预计 2027 毕业与已完成本科可以分别参与资格判断；
- 能列出连续招聘单位、岗位族及其支撑年份；
- 能统计公告、报名、笔试和面试月份；
- 能统计笔试、科目、专业测试与面试方式；
- 能比较关键要求的年度变化。

### 14.3 2027 决策

- 输出 Top 20 历史参考岗位；
- 输出 2027 重点关注单位、岗位族和时间窗口；
- 每项预测显示样本数、证据强度和历史证据；
- 输出当前材料缺口、备考方向和下一步行动；
- 不把决策指数描述为录取概率。

### 14.4 用户体验

- 首页在不进入数据管理页的情况下回答“什么时候、有什么、能否报、考什么、现在做什么”；
- 历史岗位可以搜索、筛选、排序和跨年比较；
- 详情默认不展示英文内部字段和 JSON；
- 采集、匹配、核验、预测和行动状态不再使用互相矛盾的总数；
- Agent 不再用空可信池否定已经存在的历史匹配结果；
- `MODEL_UNAVAILABLE` 不进入人工业务复核列表。

### 14.5 关键 Given-When-Then 场景

**AC-COVERAGE-001：缺失年度不是零招聘**

- Given 某来源 2025 年状态为 `ACCESS_FAILED`；
- When 用户查看该单位三年复招矩阵；
- Then 2025 显示“覆盖缺失”，复招次数不把该年作为已确认的零值，预测证据强度随之下降。

**AC-ELIG-001：生日日期未知的临界年龄**

- Given 候选人出生于 1992 年 12 月但日期未知，岗位按 2027 年 9 月某日计算年龄；
- When 规则无法在整个月范围内得出同一结论；
- Then 状态为 `UNCERTAIN`，列出需补具体出生日期，不得输出可报或不可报。

**AC-FORECAST-001：预测不发生时间穿越**

- Given 系统以 2025-12-31 为 `as_of_date` 回测 2026；
- When 2026 公告或后续修订已存在于当前数据库；
- Then 预测输入排除所有 2026 才可获得的事实，并保留所用数据版本清单。

**AC-FORECAST-002：小样本不包装成概率**

- Given 某单位 × 岗位族只有 2 个独立历史招聘事件；
- When 生成 2027 机会信号；
- Then 页面只列两次历史事实，不显示百分比、确定日期或高置信度标签。

**AC-DRILL-001：图表结论可核验**

- Given 招聘规律页显示“4–5 月为常见公告月份”；
- When 用户点击该区间；
- Then 页面列出构成统计的事件、年份、日期、单位、岗位与官方来源，并显示未纳入的数据及原因。

**AC-UX-001：候选人完成核心任务**

- Given 已导入通过质量门的三年数据和已确认画像；
- When 候选人从首页选择一个重点机会；
- Then 她能在三分钟内找到预计窗口、历史岗位、资格判断、考试方式、材料缺口和下一步行动，全程不进入数据管理页。

**AC-DEGRADE-001：刷新失败保留可用结果**

- Given 首页已有上次成功计算结果；
- When 模型或某官方来源刷新失败；
- Then 页面保留上次结果，标记最后成功时间与部分/陈旧状态，不显示空白或全零，不创建空人工审核任务。

## 15. 测试策略

- Golden Dataset：选择至少 10 份覆盖 2024–2026 的官方公告与附件，人工标注时间、资格、考试方式和用工性质；
- 来源契约测试：每个来源年度夹具验证发现、原件哈希、版本、解析、reject port 和重放幂等；
- 数据质量测试：稳定键唯一、父子引用完整、日期/人数/枚举有效、公告与附件冲突、年度覆盖状态和异常记录量；
- 对账测试：公告总人数、附件行数、解析行数、入库数、拒绝数与去重数可以闭合；
- 解析测试：Excel、HTML、PDF 的字段与证据；
- 规则测试：预计毕业、双教育经历、临界年龄、境外学历、应届定义和职称；
- 历史聚合测试：连续三年、两年、单年、年份缺失和机构名称映射；
- 预测测试：证据强度、样本数、时间窗口以及禁止生成具体未发布日期；
- 历史回测：2024 → 2025、2024–2025 → 2026，验证时间切分、Top-K 命中、窗口命中和结构变化降级；
- API 测试：年度筛选、跨年比较、Top 20 和行动建议；
- 性能测试：10,000 岗位规模下验证列表/聚合 API 与首页 P95；
- UI 测试：真实候选人路径、URL 状态恢复、图表下钻、详情、预测证据、陈旧状态、键盘路径和移动端；
- 真实数据验收：从首页完成“发现机会 → 查看依据 → 判断资格 → 查看考试 → 得到下一步行动”的完整流程。

## 16. 完成定义

本阶段只有在真实候选人能够打开 Career OS 并直接得到以下结果时才算完成：

- 过去三年符合方向的岗位与单位；
- 重复招聘规律和招聘时间窗口；
- 2027 年重点关注清单；
- 历史报考要求、笔试与面试方式；
- 对候选人条件的明确判断与待确认项；
- 当前至 2027 年的准备顺序和行动清单；
- 每个重要结论的官方证据。

“采集成功”“测试通过”或“数据库已有大量岗位”均不能单独作为产品完成标准。
