# 2024–2026 历史机会研究与 2027 求职预测设计

**状态：** 已批准  
**数据年度：** 2024、2025、2026  
**预测年度：** 2027  
**首位候选人：** 1992 年 12 月出生、女性、计算机相关本科与境外硕士背景  
**目标：** 将 Career OS 从实时采集与审核后台，调整为能够回答“过去三年有什么规律、2027 年可能有什么机会、我能不能报、什么时候考试、现在该准备什么”的个人职业研究与行动系统。

## 1. 问题定义

当前系统已经能够采集浙江省人社厅和杭州市人社局公告、下载官方附件、解析 Excel 岗位并保留证据，但产品闭环尚未成立：

- 岗位库、已核验岗位、候选人匹配和可信机会使用不同口径，用户同时看到“数千条记录”“12 个匹配”和“0 个可信机会”；
- 历史数据没有按招聘年度组织，无法比较单位复招、要求变化、招聘月份和考试方式；
- 当前候选人仍是单一最高学历的 Seed Profile，无法表达本科与预计毕业的境外硕士两段教育经历；
- 抽取模型不可用时，人工审核队列出现“置信度 0%、0 个岗位”的不可操作任务；
- 决策助手只读取空的可信机会池，无法利用已有的候选人匹配与历史岗位回答问题；
- 页面优先呈现采集状态和技术证据，而不是求职者需要的机会、时间、资格、考试和行动。

本阶段不以扩大实时抓取数量为首要目标，而以形成可靠的三年历史样本和可解释的 2027 行动建议为目标。

## 2. 产品结果

系统必须能够稳定回答以下问题：

1. 2024–2026 年浙江、重点杭州出现过哪些稳定计算机技术岗位？
2. 哪些单位或岗位族连续招聘、隔年招聘或只出现一次？
3. 公告、报名、笔试和面试通常集中在哪些月份？
4. 哪些岗位有笔试，考什么；哪些有专业测试或只有面试？
5. 年龄、学历、专业、应届、境外学历、工作经历和职称要求如何变化？
6. 根据历史证据，2027 年哪些时间窗口、单位和岗位族值得重点监控？
7. 结合候选人画像，哪些岗位可报、条件可满足、需要确认或明确不符合？
8. 用户现在应准备哪些材料、考试内容和时间提醒？

## 3. 产品边界

### 3.1 本阶段包含

- 2024、2025、2026 三个招聘年度的官方公告与岗位附件；
- 浙江全省，杭州优先；
- 事业单位、政府直属信息中心、医院信息中心、高校正式信息化岗位、科研院所工程技术岗位以及有正式用工证据的政府背景技术岗位；
- 计算机、软件、数据、人工智能、网络安全、信息化、信息系统和数字政府相关岗位；
- 历史时间、资格、考试方式、用工性质和单位复招规律；
- 基于历史频率与时间分布的 2027 预测；
- 候选人资格判断、条件缺口与备考行动。

### 3.2 本阶段不包含

- 自动报名或自动提交个人信息；
- 没有历史样本支持的录取概率；
- 对未发布的 2027 具体日期作确定性承诺；
- 用“看起来像事业单位”推断事业编制；
- 全国范围招聘扩张；
- 复杂机器学习预测模型；
- 在缺少模型配置时生成伪 Agent 结果。

## 4. 正式候选人画像

### 4.1 已确认事实

- 性别：女；
- 出生：1992 年 12 月，具体日期未知；
- 本科：计算机科学与技术，2014 年毕业；
- 硕士：示例海外大学，计算机科学专业，预计 2027 年毕业；
- 工程背景：Java 后端、企业级软件开发、数据库、信息系统；
- 研究背景：人工智能、图神经网络、机器学习实验；
- 职称：中级计算机应用，通过评审取得；
- 地点优先级：杭州第一，浙江其次，江苏、广东、福建为扩展地区；
- 目标：事业单位专业技术岗、政府信息与数据中心、数字政府、科研院所工程技术、高校正式信息化、医院信息中心、政府背景国企正式技术岗；
- 排除：劳务派遣、短期项目制、纯行政、纯销售、博士限定科研岗、高校纯教师岗。

### 4.2 待确认事实

- 具体出生日期；
- 示例海外大学预计毕业月份、学位取得时间和留服认证计划；
- 工作经历年限与可提供的合同、社保等证明；
- 2027 年报考时的在职、社保和应届身份；
- 可作为资格或竞争证据的项目、论文、证书与技能材料。

待确认事实不得被转成否定事实。遇到年龄截止日接近 9 月、应届定义依赖学位取得日期或经历证明不足时，资格结果必须是 `UNCERTAIN`，并明确告诉用户需要补充什么。

### 4.3 画像模型

候选人从单一 `highestEducation + graduationYear` 升级为可重复的 `EducationRecord`：

- `institution_name`
- `country_or_region`
- `education_level`
- `major_name`
- `graduation_year`
- `graduation_month`
- `completion_status`：`COMPLETED`、`EXPECTED`
- `credential_verification_status`：`NOT_REQUIRED`、`PLANNED`、`IN_PROGRESS`、`VERIFIED`、`UNKNOWN`

保留候选人主专业、技能、研究方向、职称、地点和用工偏好作为独立事实。每项事实保留确认状态与确认时间。

## 5. 历史数据模型

### 5.1 RecruitmentEvent

一个招聘事件代表一份公告及其公共流程，至少包含：

- 招聘年度、公告标题、发布单位、发布日期；
- 报名开始与截止、资格审查、缴费、准考证、笔试、面试相关时间；
- 报名入口；
- 笔试科目、面试方式、专业测试；
- 应届生范围、境外学历、工作经历证明和聘用规则；
- 官方公告链接、附件集合、内容指纹和抓取时间。

### 5.2 JobPosting

一个岗位代表附件中的一行或公告中独立的岗位，至少包含：

- 单位、主管部门、岗位名称、岗位代码、招聘人数；
- 岗位族、岗位类别、岗位等级、工作地点；
- 学历、学位、专业、年龄、性别、应届、经历、职称和其他条件；
- 是否笔试、笔试科目、是否专业测试、面试入围比例；
- 用工性质与对应证据；
- 招聘年度与招聘事件关联；
- 稳定岗位键、内容指纹、有效状态与字段级证据。

### 5.3 历史分析读模型

新增只读分析结果，不污染官方事实：

- `OrganizationYearPresence`：单位在每个年度是否招聘目标岗位；
- `JobFamilyYearPresence`：单位与岗位族在每个年度的岗位数量；
- `RecruitmentWindow`：公告、报名、笔试、面试的月份与间隔；
- `RequirementTrend`：年龄、学历、专业、应届、经历、职称要求的年度变化；
- `ExamPattern`：笔试、科目、专业测试和面试方式的历史分布；
- `CandidateHistoricalFit`：候选人在历史公告当年的可报状态和原因；
- `ForecastSignal`：2027 时间窗口、单位、岗位族、置信度及支撑证据。

分析结果可重新计算，不作为官方事实来源。

## 6. 数据获取与回填

### 6.1 数据源优先级

1. 浙江省人力资源和社会保障厅；
2. 杭州市人力资源和社会保障局；
3. 杭州重点区县政府与人社部门；
4. 重点高校、医院、科研院所和政府直属单位官网；
5. 政府背景国企官网，仅纳入能确认正式用工的岗位。

第三方招聘网站只用于发现线索，不作为最终资格证据。

### 6.2 年度回填流程

```text
年度入口与站内搜索发现
  → 公告归档
  → 官方附件下载
  → 公告公共规则解析
  → Excel/PDF 岗位结构化
  → 稳定岗位键与内容指纹
  → 字段级证据
  → 候选人历史资格判断
  → 年度聚合
  → 2027 预测信号
```

2024、2025、2026 使用相同解析和证据标准。历史附件失效时，保留已获取文件的内容哈希、原始 URL 和抓取记录，并将可访问性与事实可信度分开表示。

### 6.3 审核原则

- 只把影响候选人资格、用工性质、考试方式和预测规律的冲突送入人工复核；
- 已由 Excel 明确提供的岗位不得因为公告 LLM 抽取失败而回退成“0 个岗位”；
- `MODEL_UNAVAILABLE` 是系统运行错误，不是用户可审核的业务任务；
- 空提案不能执行“确认并入库”；
- 审核按字段或冲突分组，不要求用户重新录入整份公告。

## 7. 资格判断

资格引擎对每个历史或未来岗位输出：

- `ELIGIBLE`：已确认事实满足全部硬条件；
- `CONDITIONALLY_ELIGIBLE`：预计毕业、留服认证或材料在截止前完成即可满足；
- `UNCERTAIN`：缺少具体出生日期、毕业月份、经历证明等关键事实；
- `INELIGIBLE`：有明确硬条件不符；
- `NOT_TARGET`：岗位不属于目标技术与稳定用工范围。

规则引擎负责年龄、学历、专业、毕业年份、经历、职称和性别等确定性判断。LLM 只解析规则原文与生成解释，不覆盖规则结果。

对于 2027 年预测岗位，在正式公告发布前只输出“历史上通常要求”和“需要提前准备”，不得提前给出确定的 `ELIGIBLE`。

## 8. 2027 预测方法

第一版使用透明的统计与规则信号，不使用黑盒预测：

### 8.1 单位复招信号

- 三年均出现同一目标岗位族：高置信度；
- 三年中出现两年：中置信度；
- 只出现一年：低置信度；
- 同一单位名称变更或机构合并需有明确映射证据。

### 8.2 时间窗口信号

- 使用历史公告、报名、笔试和面试日期的月份分布；
- 输出最常见月份范围和样本数量；
- 样本少于两个年度时不得标为高置信度；
- 2027 具体日期在公告发布前显示为预测窗口，不显示为截止日期。

### 8.3 要求趋势信号

- 比较同一单位与岗位族三年的学历、年龄、应届、经历和职称要求；
- 区分稳定要求、趋严、趋宽和样本不足；
- 所有趋势必须列出对应年份和原始岗位。

### 8.4 机会优先级

2027 关注优先级由以下维度组成：

- 历史复招强度；
- 目标岗位族匹配；
- 历史资格可满足程度；
- 用工稳定性证据；
- 地点优先级；
- 考试准备复用度；
- 证据覆盖和样本数量。

分数是机会决策指数，不是录取概率。每个分项必须可解释。

## 9. Agent 设计

### 9.1 Historical Recruitment Analysis Agent

输入候选人、时间范围和问题，使用结构化历史数据回答：

- 哪些单位连续招聘；
- 哪些月份需要关注；
- 哪些岗位族最常出现；
- 要求和考试方式如何变化；
- 结论由哪些年份和公告支撑。

### 9.2 Eligibility and Action Agent

基于候选人事实、岗位规则和时间窗口回答：

- 当前是否具备资格；
- 哪些条件预计可在 2027 年满足；
- 还缺哪些事实或材料；
- 何时准备留服认证、报名材料和考试；
- 建议的下一步行动。

### 9.3 运行约束

- Agent 只读取可引用的结构化事实和证据；
- 返回 Typed DTO，并为结论附证据 ID；
- 无模型配置时明确显示 Agent 不可用，同时保留确定性分析结果；
- 不得用“可信池为空”覆盖已有的候选人历史匹配；
- 不得把预测窗口表述成确定公告日期；
- 不执行自动报名。

## 10. 用户界面

### 10.1 我的 2027 机会

首页直接呈现：

- 下一个预计招聘窗口及倒计时；
- 2027 重点关注单位与岗位族；
- 近三年重复招聘证据；
- 当前资格优势、条件缺口与材料准备；
- 本月、本季度和公告发布后的行动清单。

首页不得以采集记录数、数据库状态或空的 T1/T2/T3 为主要信息。

### 10.2 三年历史岗位库

提供年份、地区、单位、岗位族、学历、年龄、应届、境外学历、笔试、专业测试和用工性质筛选；支持按公告时间、匹配程度、单位复招次数排序，并支持跨年度比较。

岗位列表优先显示：单位、岗位、年份、是否历史可报、学历/年龄、是否笔试、报名与考试时间。技术证据不在列表中展开。

### 10.3 招聘规律

- 年度与月份时间线；
- 公告、报名、笔试、面试月份热力图；
- 连续招聘单位与岗位族；
- 要求变化矩阵；
- 笔试科目、专业测试和面试方式统计；
- 每个图表可回到构成它的历史岗位。

### 10.4 备考与行动

- 预计关注窗口；
- 报名材料清单；
- 留服认证与毕业材料节点；
- 常见笔试科目与复习计划；
- 专业测试和面试准备；
- 关注、准备中、已报名、已考试、已结束状态管理。

### 10.5 岗位详情

默认只展示：

1. 历史当年能否报名及原因；
2. 公告、报名和考试时间；
3. 是否笔试、考什么、是否专业测试；
4. 全部报考要求；
5. 用工性质；
6. 对 2027 准备的参考意义；
7. 官方公告与附件。

字段英文名、JSON locator、内容指纹和解析版本放入折叠的“高级证据”区域。

### 10.6 数据管理后台

官方来源运行、手工导入、迁移状态、模型错误和技术审核从主要导航移入数据管理区域。普通用户不需要理解数据准入状态机。

## 11. 状态口径

系统分别维护但不混淆：

- 数据是否成功采集；
- 岗位是否成功结构化；
- 关键字段是否有证据；
- 是否属于目标岗位；
- 候选人历史资格状态；
- 是否值得在 2027 关注；
- 用户行动状态。

页面中的总数必须注明统计口径和年度范围。历史分析不得被“可信机会准入”完全阻断；未知或有冲突的事实可以参与样本计数，但不得支持确定性资格结论。

## 12. 失败与降级

- 单个公告或附件失败不阻断同一来源其他文档；
- 官方链接失效时显示已归档证据和失效状态；
- LLM 不可用时继续完成 Excel 解析、规则判断、历史聚合和统计预测；
- 样本不足时输出“样本不足”，不输出百分比概率；
- 候选人事实缺失时输出待补事实与影响范围；
- 历史数据尚未补齐时，页面显示年度覆盖率，不把缺失年度解释为“当年没有招聘”。

## 13. 实施顺序

1. 正式候选人教育经历与已确认事实；
2. 统一历史年度、时间、考试和要求字段；
3. 2024、2025 数据源发现与回填；
4. 历史资格读模型和筛选查询；
5. 单位复招、时间窗口、要求趋势与考试模式聚合；
6. 2027 透明预测信号；
7. 重做“我的 2027 机会”和历史岗位库；
8. 招聘规律与备考行动；
9. 接通两个 Agent，并完成证据引用与无模型降级；
10. 真实用户验收与数据质量抽样。

## 14. 验收标准

### 14.1 数据

- 2024、2025、2026 三个招聘年度均可检索；
- 至少 30 个重点单位；
- 至少 200 个目标技术岗位；
- 至少 80% 的纳入岗位有官方公告或附件证据；
- 页面显示各年度覆盖率，不将采集缺口解释为零招聘；
- 同一岗位重复运行不产生重复历史记录。

### 14.2 资格与历史分析

- 年龄、学历、专业、性别、应届、境外学历、经历和职称均有规则结果；
- 具体出生日期未知时，临界年龄结论不会被误判为可报或不可报；
- 预计 2027 毕业与已完成本科可以分别参与资格判断；
- 能列出连续招聘单位、岗位族及其支撑年份；
- 能统计公告、报名、笔试和面试月份；
- 能统计笔试、科目、专业测试与面试方式；
- 能比较关键要求的年度变化。

### 14.3 2027 决策

- 输出 Top 20 历史参考岗位；
- 输出 2027 重点关注单位、岗位族和时间窗口；
- 每项预测显示样本数、置信度和历史证据；
- 输出当前材料缺口、备考方向和下一步行动；
- 不把决策指数描述为录取概率。

### 14.4 用户体验

- 首页在不进入数据管理页的情况下回答“什么时候、有什么、能否报、考什么、现在做什么”；
- 历史岗位可以搜索、筛选、排序和跨年比较；
- 详情默认不展示英文内部字段和 JSON；
- 采集、匹配、核验、预测和行动状态不再使用互相矛盾的总数；
- Agent 不再用空可信池否定已经存在的历史匹配结果；
- `MODEL_UNAVAILABLE` 不进入人工业务复核列表。

## 15. 测试策略

- Golden Dataset：选择至少 10 份覆盖 2024–2026 的官方公告与附件，人工标注时间、资格、考试方式和用工性质；
- 解析测试：Excel、HTML、PDF 的字段与证据；
- 规则测试：预计毕业、双教育经历、临界年龄、境外学历、应届定义和职称；
- 历史聚合测试：连续三年、两年、单年、年份缺失和机构名称映射；
- 预测测试：置信度、样本数、时间窗口以及禁止生成具体未发布日期；
- API 测试：年度筛选、跨年比较、Top 20 和行动建议；
- UI 测试：真实候选人路径、历史筛选、详情、预测证据和移动端；
- 真实数据验收：从首页完成“发现机会 → 查看依据 → 判断资格 → 查看考试 → 得到下一步行动”的完整流程。

## 16. 完成定义

本阶段只有在真实候选人能够打开 Career OS 并直接得到以下结果时才算完成：

- 过去三年符合方向的岗位与单位；
- 重复招聘规律和招聘时间窗口；
- 2027 年重点关注清单；
- 历史报考要求、笔试与面试方式；
- 对本人条件的明确判断与待确认项；
- 当前至 2027 年的准备顺序和行动清单；
- 每个重要结论的官方证据。

“采集成功”“测试通过”或“数据库已有大量岗位”均不能单独作为产品完成标准。
