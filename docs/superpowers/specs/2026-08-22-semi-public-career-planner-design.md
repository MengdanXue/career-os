# Career OS 半体制职业规划工作台设计

**状态：** 待书面确认  
**阶段：** Phase 5A — Personal Career Planner  
**目标年度：** 2027，行动范围覆盖 2026-08 至 2028-12  
**上位规范：** `docs/CAREER_OS_MASTER_SPEC.md`、`docs/superpowers/specs/2026-08-22-historical-opportunity-forecast-design.md`

## 1. 目标与成功标准

本阶段不是再增加一个按关键词找岗位的聊天框，而是把现有官方历史岗位库转成面向候选人的可执行规划。系统必须在一个页面回答：

1. 哪些半体制技术路线最适合候选人；
2. 2027 获得境外硕士前后，分别能报什么；
3. 35、38 等年龄规则对应的有效报考窗口；
4. 历史公告、报名、笔试和面试集中在哪些月份；
5. 哪些资格与材料已经满足，哪些尚缺证据；
6. 从现在到 2028 年每个阶段应做什么。

成功标准不是“接口返回 200”或“页面能打开”，而是候选人无需进入数据管理后台，即可看到有历史样本、官方链接、数据截至日期和不确定性说明的半体制规划，并能从规划下钻到具体历史岗位详情。

## 2. 已确认画像与事实边界

### 2.1 已确认事实

- 性别：女；
- 出生日期：1992-12-31；
- 本科：计算机科学与技术，2014 年完成；
- 硕士：示例海外大学计算机科学专业，预计 2027 年毕业；
- 境外学历认证：计划办理，未完成前不得视为已认证硕士；
- 技术方向：Java 后端、企业级软件、数据库、信息系统、金融科技；
- 研究方向：AI、GNN、机器学习实验；
- 职称：中级“计算机应用（评审）”；
- 地点优先级：杭州第一、浙江第二；
- 目标用工：事业单位正式聘用/编制、高校与医院正式技术岗位、科研院所技术岗位、政府背景国企正式技术岗位；
- 排除：劳务派遣、短期项目、纯行政、销售、博士硬门槛、高校纯教师。

### 2.2 不得推断的事实

- 2022 年以后以读研为主，不得把简历中写到 2026 年的任职区间自动当作连续全职工作经历；
- 工作年限只计算有合同、社保、单位证明或其他可接受证据覆盖的区间；
- 党员身份未知，党员限定岗位不得判定为可报；
- 境外硕士毕业月份和留服认证完成日期尚未确认；
- “未落实工作单位”、社保与应届身份按每份公告原文判断，不从读研状态推断。

缺少上述事实时，系统输出 `UNCERTAIN` 或 `CONDITIONALLY_ELIGIBLE`，并列出需要补充的材料；禁止将未知默认成满足或不满足。

## 3. 方案取舍

考虑三种方案：

1. **聊天式规划报告：** 开发快，但无法复算、下钻和随新公告更新，拒绝作为正式产品方案；
2. **确定性规划工作台：** 复用现有候选人、招聘事件、岗位、证据与历史数据，通过规则和统计生成规划；本阶段采用；
3. **LLM/机器学习预测 Agent：** 三年稀疏样本不足以校准具体概率，留到有重复招聘、报名与结果数据后再评估。

本阶段不引入新的模型、向量库或外部运行时。LLM 可在未来润色解释，但不能参与年龄、学历、工作年限、认证日期和资格结论计算。

## 4. 规划场景

同一候选人必须同时生成三个资格场景，不能用单一 `highestEducation` 覆盖整个时间线：

### 4.1 `PRE_GRADUATION`

- 已完成学历：本科；
- 硕士：预计取得；
- 适用时间：硕士学位取得前；
- 可进入本科及以上岗位；
- 硕士硬门槛岗位只能是条件可报或不符合，取决于公告允许的证书取得期限。

### 4.2 `DEGREE_PENDING_VERIFICATION`

- 境外硕士证书已取得；
- 留服认证处于 `PLANNED` 或 `IN_PROGRESS`；
- 公告要求报名截止前完成认证时不得判为可报；
- 公告允许在指定后续日期补齐时可判为条件可报。

### 4.3 `MASTER_VERIFIED`

- 境外硕士已完成留服认证；
- 可参与硕士岗位资格判断；
- 仍需独立判断专业、年龄、应届、经历、职称、党员和其他条件。

每个场景携带 `asOfDate`、画像版本和资格规则版本。页面不得把未来场景显示为当前已满足。

## 5. 历史参考类与目标岗位口径

规划统计只纳入同时满足以下条件的岗位：

- 招聘年度为 2024、2025、2026；
- 学历门槛为本科或硕士；
- 专业原文或标准化专业包含计算机、软件、网络安全、数据、人工智能或相关电子信息方向；
- 岗位名称、岗位族或职责属于信息系统、软件、数据、网络安全、IT 运维、数字化技术；
- 用工性质有正式证据或明确显示 `UNKNOWN`，但未知岗位不得计入“正式岗位数”；
- 排除博士要求、教师、博士后、劳务派遣、短期项目和明显非技术岗位。

历史岗位数是“参考机会规模”，不是候选人的可报数量。资格场景计算后才形成个人可报、条件可报、待确认和不符合数量。

页面必须同时展示：样本岗位数、独立招聘事件数、来源年度覆盖状态、关键字段证据覆盖率和数据截至日期。来源年度未完成时，不得把缺失解释成零招聘。

## 6. 路线模型

第一版固定生成四条路线：

1. `PUBLIC_TECH`：市属、省属和区县事业单位信息化、软件、数据与系统技术岗；
2. `UNIVERSITY_HOSPITAL_IT`：高校与医院正式非教师信息化岗位；
3. `RESEARCH_SUPPORT`：科研院所、质量技术、科技服务和工程技术支撑岗位；
4. `GOVERNMENT_SOE_DIGITAL`：政府背景国企、数据集团与数字化平台正式技术岗。

每条路线输出：

- 历史岗位数和正式岗位数；
- 涉及单位和岗位族；
- 适配场景；
- 年龄、学历、专业、经历和职称要求分布；
- 典型考试方式；
- 历史月份；
- 代表岗位 ID 与官方来源；
- 候选人优势、资格风险和准备重点；
- `evidenceStrength`：`STRONG`、`MODERATE`、`LIMITED`、`INSUFFICIENT`。

路线排序使用透明的决策指数，不使用录取概率：

```text
RoutePriority =
  0.30 * eligibility_readiness
  + 0.25 * experience_advantage
  + 0.20 * employment_stability
  + 0.15 * historical_supply
  + 0.10 * preparation_reuse
```

每个分项显示计算依据。样本不足或用工性质未知时降低证据强度，不补写主观分数。

## 7. 年龄窗口

年龄由确定性规则按完整出生日期、岗位年龄上限和公告参考日期计算。规划层可对未来年度生成“如果规则保持不变”的情景窗口，但必须带条件说明。

第一版至少展示：

- 2027、2028、2029、2030、2031 年春季参考日期下，35、38、40 周岁规则的资格状态；
- 当前年度历史公告使用过的年龄阈值分布；
- 政策由 35 放宽到 38 等变化的历史事实；
- 每个预测窗口的依据与“不保证下一年政策不变”提示。

未来公告发布后，预测窗口立即由正式公告规则替换，并保留预测与实际差异。

## 8. 招聘与考试日历

系统从 `RecruitmentEvent` 生成以下历史信号：

- 公告月份；
- 报名开始与截止；
- 报名窗口天数；
- 笔试日期及报名截止到笔试的间隔；
- 笔试科目；
- 专业测试与面试比例。

只有日期完整的独立招聘事件参与天数计算。日期不完整时只显示已知月份或“未知”，不插值。

行动日历按以下顺序生成：

1. 现在至 2026-12：画像与材料证据、统考基础准备；
2. 2027-01 至集中公告：官方来源监控、报名材料定版；
3. 公告发布至报名截止：岗位资格复核与报名动作；
4. 报名后至笔试：按历史科目生成复习重点；
5. 2027 毕业后：学位取得、留服认证、硕士岗位切换；
6. 2027 下半年：高校、医院、区县和特殊技术招聘；
7. 2028 春季：第二个完整集中招聘周期。

预测月份使用“预计关注窗口”，正式日期才允许显示倒计时和截止提醒。

## 9. 画像模型补充

### 9.1 CandidateProfile

新增或正式启用：

- `gender`：`FEMALE`、`MALE`、`OTHER`、`UNKNOWN`；
- `politicalAffiliation`：至少支持 `CPC_MEMBER`、`CPC_PROBATIONARY`、`NON_MEMBER`、`UNKNOWN`；
- 已存在的 `birthDay` 设置为 29；
- 教育记录保存预计毕业月份与留服状态。

### 9.2 CandidateEmploymentRecord

新增独立工作经历模型，不再依赖一个总工作年限：

- 单位、岗位、开始与结束日期；
- 全职、兼职、实习或未知；
- 可用于资格计算的工作内容标签；
- 证明状态：`UNVERIFIED`、`PARTIAL`、`VERIFIED`、`REJECTED`；
- 可提供的证明类型元数据，不默认上传敏感原件。

规划层只累计与岗位要求相关且证明状态允许的区间。重叠工作与读研时间必须显示冲突提示，不自动删除，也不重复累计。

### 9.3 候选人确认事实

确认键增加 `GENDER`、`POLITICAL_AFFILIATION`、`EMPLOYMENT_HISTORY`。任何更新都提升画像版本并使依赖旧画像的规划结果失效。

## 10. 后端设计

新增只读 `CareerPlanService`，放在 `career-application`，依赖一个有界的 `CareerPlanQueryPort`，不直接依赖 JPA 或 Web。

`CareerPlanQueryPort` 从现有候选人、教育、招聘事件、岗位、单位、证据和历史覆盖账本读取快照。`career-infrastructure` 使用只读投影查询完成聚合；规划结果第一版按请求复算，不新建预测事实表。

公开接口：

```http
GET /api/v1/candidates/{candidateId}/career-plan
    ?targetYear=2027
    &asOf=2026-08-22
```

响应至少包含：

```text
candidateSnapshot
currentScenario
futureScenarios
recommendedRoutes
ageWindows
recruitmentWindows
examPatterns
historicalSummary
qualificationRisks
actionTimeline
dataCoverage
generatedAt
algorithmVersion
```

代表岗位只返回岗位 ID、必要摘要和证据链接；完整详情复用现有岗位详情 API，避免复制两套事实口径。

参数校验：目标年度只能在当前年度至当前年度后五年之间；`asOf` 不能晚于服务器当前日期。候选人不存在返回 404，数据不足返回可解释的部分结果，不返回伪造的全零规划。

## 11. 前端设计

主导航新增“我的规划”，路由为 `/plan`。页面按以下固定顺序组织：

1. **结论：** 当前最推荐路线、关键年龄窗口、下一个关注期；
2. **三种资格场景：** 本科阶段、硕士待认证、硕士已认证；
3. **为什么：** 三年岗位供给、正式用工数量、单位类型和月份规律；
4. **风险：** 留服、工作证明、党员、毕业月份、专业口径等；
5. **行动：** 现在至 2028 年的材料、监控、笔试和面试计划；
6. **官方依据：** 可下钻的代表岗位和公告。

页面不使用装饰性复杂图表。年度岗位量用小型柱形图或表格，月份用时间线，路线用可比较卡片。所有图形提供文字值，状态不只依赖颜色。

缺失或部分覆盖必须显示为“数据尚未补齐”，不能显示为“0 个机会”。刷新失败时保留上次成功结果并标记陈旧时间。

## 12. 失败与降级

- 历史来源年度不完整：显示覆盖缺口，路线仍可基于完整切片生成低证据强度结果；
- 年龄参考日期缺失：只展示年龄要求原文，不给确定资格；
- 工作经历未核验：经历优势可显示为“待证明”，不得用于确定资格通过；
- 硕士未认证：严格使用对应资格场景；
- LLM 不可用：不影响规划生成；
- 单个聚合查询失败：返回其他已成功区块并标记错误区块；
- 没有目标岗位：区分“完整来源确认无岗位”和“数据未覆盖”。

## 13. 隐私与安全

- 出生日期、性别、教育、工作证明状态仅保存在本地私有环境；
- API 和日志不得输出身份证号、手机号、证书编号或证明原件；
- 规划页面不提供公开分享链接；
- 官方来源与个人证据分开存储；
- 不自动报名、不自动提交个人资料。

## 15. 测试策略

- 领域测试：生日边界、教育场景、留服状态、工作区间重叠与证明状态；
- 应用服务测试：路线排序、样本门控、招聘窗口、行动时间线、数据覆盖降级；
- 持久化测试：三年聚合口径、目标岗位过滤、正式用工数量、代表岗位下钻；
- API 测试：默认请求、目标年度校验、候选人不存在、部分数据响应；
- UI 测试：规划阅读顺序、场景切换、风险提示、岗位下钻、加载/错误/陈旧状态；
- 真实数据 Golden Test：至少包含“中级职称 + 两年经历”的信息技术岗、“硕士 + 信息化管理”岗、应届限定岗、党员限定岗和留服截止日期岗；
- 回归测试：现有机会池、画像、更新岗位库和岗位详情保持可用。

## 16. 本阶段不做

- 不预测某个单位 2027 一定招聘；
- 不输出录取概率；
- 不自动投递或报名；
- 不构建完整材料文件管理系统；
- 不扩展全国数据源；
- 不引入 Elasticsearch、Kafka、工作流引擎或新的 AI 框架；
- 不用简历里未经确认的重叠时间线自动补候选人事实。

## 17. 完成定义

只有当真实候选人在 `/plan` 中能明确看到“我现在处于哪个资格场景、主攻哪些路线、年龄窗口还有多久、什么时候重点关注、通常考什么、缺哪些材料、下一步做什么”，且每个关键历史结论可下钻到官方岗位时，本阶段才完成。

测试通过、接口存在或数据库岗位很多，均不能单独作为完成证据。
