# Career OS 杭州来源、招聘生命周期与 2027 政策证据 Wave 2 设计

**日期：** 2026-08-24

**状态：** 用户已确认杭州优先，待书面规格复核

**范围：** 杭州市、杭州各区县、驻杭省属单位，以及直接影响杭州报考资格的国家/浙江省/杭州市政策

## 1. 目标

本期将 Career OS 从“能采集部分杭州招聘公告”升级为“能够持续发现、核实并跟踪杭州稳定技术岗位完整招聘过程的个人职业决策系统”。

系统必须服务以下候选人目标：2027 年毕业的境外计算机硕士，出生于 1992 年 12 月，具有计算机本科、Java 后端与企业信息系统经验、AI/GNN 研究经历和计算机应用中级职称，优先寻找杭州的高稳定技术岗位。

目标岗位包括：

- 事业单位编制内计算机、软件、数据、AI 应用和信息化专业技术岗；
- 政府直属信息中心、大数据中心、数字政府与公共数据机构技术岗；
- 科研院所正式工程技术、信息化和科研支撑岗；
- 高校正式信息化、实验技术和工程技术岗；
- 医院信息中心、数据中心、软件与网络安全岗；
- 强政府背景数字化平台和市属国企正式技术岗。

默认不推荐劳务派遣、短期项目制、纯博士科研岗、纯行政岗、教师岗、销售岗及明显无关岗位。原始事实仍保留，排除发生在准入和推荐层，不能发生在采集层。

## 2. 本期范围边界

### 2.1 地理范围

本期只实施杭州：

- 杭州市属；
- 上城、拱墅、西湖、滨江、萧山、余杭、临平、钱塘、富阳、临安；
- 建德、桐庐、淳安作为杭州完整性扩展，优先级低于主城区但进入来源目录；
- 驻杭省属事业单位、高校、医院、科研院所和省属国企；
- 直接约束杭州岗位的国家、浙江省和杭州市政策。

江苏、福建、广东和浙江其他城市不在本期实施，但数据模型不得硬编码为杭州专用，后续扩省不需要改表结构或 API 契约。

### 2.2 时间范围

- 历史基线：2024、2025、2026 三个自然年度；
- 当前监控：2026 年发布、面向 2027 届或报名/考试发生在 2027 年的公告；
- 前瞻窗口：所有包含“2027 届”“2027 年毕业”“提前批”“校园招聘”“招聘预告”的官方内容；
- 增量频率：来源每日扫描，用户周报只显示新增、重要变化、截止临近和政策变化。

如果一周内没有高匹配新岗位，报告必须只显示重要规则变化；二者都没有时明确显示“本周暂无值得关注的新机会”，不得用低质量岗位填充。

## 3. 当前缺口

当前目标来源目录登记 20 个来源，但只有 5 个存在可运行的 `recruitment_source`。已运行来源只有浙江省人社厅、杭州市人社局、杭州电子科技大学、浙江工商大学和杭州市第一人民医院；杭州区县、科研院所、市属国企和主管部门直连均未形成有效覆盖。

当前来源配置还通过 `titleExcludeRegex` 排除“成绩、资格复审、面试、体检、递补、拟聘、公示”等通知。这会造成招聘事件只有岗位表，没有考试与录用过程，不能回答笔试科目、面试形式、总成绩公式、体检、公示和最终录用。

`policy_rule` 当前没有真实政策记录。应届身份、境外学历、留服认证、未落实工作单位、社保、年龄计算和专业目录只能依赖零散公告字段，无法形成版本化、按辖区生效的资格证据。

## 4. 方案选择

### 4.1 采用：三条独立管线，共享证据与事件身份

本期采用：

1. `Recruitment Acquisition`：发现招聘公告、岗位附件和当前机会；
2. `Lifecycle Acquisition`：发现成绩、复审、笔试、面试、体检、考察、公示和录用通知，并关联原招聘事件；
3. `Policy Acquisition`：采集应届、留服、社保、年龄和专业目录等政策及其修订。

三条管线共享下载器、原始工件存储、内容指纹、证据定位、来源运行账本和人工复核队列，但使用不同的解析与状态投影。招聘岗位不能因为生命周期或政策采集失败而消失；失败必须按管线和工件独立显示。

### 4.2 不采用：扩大标题关键词后全部当招聘公告

简单删除排除词会把面试名单、公示名单和岗位计划混成同一类内容，并可能把人员姓名等不必要信息写入岗位库。本期必须先分类通知类型，再进入相应处理器。

### 4.3 不采用：为每个网站复制爬虫

来源差异限制在配置和小型发现适配器。附件下载、解析、稳定键、增量差异、证据、失败账本和调度继续走统一管线。

## 5. 杭州来源矩阵

来源按路线和优先级管理。`P0` 影响主推荐结果，`P1` 扩大稳定技术岗位覆盖，`P2` 用于完整性和补漏。

### 5.1 政府综合与主管部门

`P0`：

- 杭州市人力资源和社会保障局；
- 浙江省人力资源和社会保障厅中工作地点为杭州的招聘；
- 杭州市人事考试相关官方入口；
- 杭州市数据资源/公共数据主管体系；
- 杭州市经济和信息化主管部门；
- 杭州市发展改革主管部门；
- 杭州市科技主管部门；
- 杭州市卫生健康主管部门。

主管部门来源用于发现其直属信息中心、数据中心、事业单位和流程通知，不能仅采主管部门机关新闻。

### 5.2 区县官方来源

`P0`：滨江、余杭、钱塘、萧山、临平、西湖、拱墅、上城、富阳、临安。

`P2`：建德、桐庐、淳安。

每个区县至少登记政府门户招聘栏目、人社/组织部门入口和可验证的事业单位公告列表。多个栏目发布同一公告时建立转载关系，不重复生成招聘事件。

### 5.3 高校与医院

`P0` 高校：杭州电子科技大学、浙江工业大学、浙江工商大学、杭州师范大学，以及其他持续出现正式信息化或实验技术岗位的驻杭公办高校。

`P0` 医院：杭州市第一人民医院、杭州市中医院、杭州市儿童医院、杭州市西溪医院，以及杭州卫健主管部门公告中出现信息化岗位的市属医院。

高校和医院必须采集单位人事官网的后续考试通知，因为综合人社公告通常不能覆盖资格复审、专业测试、面试方法和成绩公式。

### 5.4 科研院所与政府背景平台

`P0`：国科大杭州高等研究院、西湖大学及杭州官方体系中具有长期组织保障的研究机构工程技术岗。

`P0` 国企/平台：杭州数据集团、杭州市国有资本投资运营体系、杭州地铁及后续经官方国资关系核验的数字政府、公共数据、城市大脑和政务云平台。

国企与平台岗位只有在官方公告明确劳动关系主体、招聘主体和正式用工口径时才能进入推荐；实习、外包、派遣和项目合作不进入推荐。

### 5.5 来源接入验收

每个来源继续使用 `REGISTERED → CONTRACT_VERIFIED → LIVE_SMOKE_VERIFIED → BACKFILL_COMPLETE → INCREMENTAL_VERIFIED` 检查点。

`CONNECTED` 必须满足：

- 2024—2026 年范围有可审计的完整遍历或明确零结果证据；
- 当前增量扫描成功；
- 招聘公告和生命周期通知的分类错误低于验收阈值；
- 附件、页面和岗位失败都有工件级或行级记录；
- 相同输入复跑没有重复事件、岗位或通知；
- 不能把单个附件部分失败显示成整个来源不可访问。

## 6. 招聘生命周期模型

### 6.1 通知类型

新增 `RecruitmentNoticeType`：

- `ANNOUNCEMENT`
- `SUPPLEMENT`
- `CORRECTION`
- `REGISTRATION`
- `QUALIFICATION_REVIEW`
- `PAYMENT`
- `ADMISSION_TICKET`
- `WRITTEN_EXAM`
- `WRITTEN_EXAM_RESULT`
- `PROFESSIONAL_TEST`
- `INTERVIEW`
- `INTERVIEW_RESULT`
- `PHYSICAL_EXAM`
- `INVESTIGATION`
- `PUBLICATION`
- `APPOINTMENT`
- `CANCELLATION`
- `OTHER`

通知分类先使用确定性标题和正文规则；无法唯一分类时进入 `REVIEW_REQUIRED`，LLM 只能在保留证据和置信度的前提下辅助分类。

### 6.2 事件关联

生命周期通知通过以下证据关联招聘事件，优先级从高到低：

1. 官方页面显式链接或公告编号；
2. 原公告标题/批次名称的规范化匹配；
3. 年份、招聘单位、岗位编号和主管部门组合；
4. 人工确认。

模糊相似度不得自动合并两个招聘批次。一个通知可以关联多个岗位，但必须先关联到唯一招聘事件；无法确定时保存在待关联队列，不能创建新的虚假岗位事件。

### 6.3 状态更新

关联成功后更新招聘事件的报名、资格复审、缴费、准考证、笔试、专业测试、面试、体检、考察、公示和聘用状态，并保存：

- 日期和时间；
- 地点或线上入口；
- 笔试科目；
- 面试/专业测试形式；
- 入围比例；
- 总成绩公式；
- 递补与取消规则；
- 官方来源及原文证据。

后续公告只补充或修订字段，不能覆盖原始版本。发生矛盾时记录 `CONFLICTING_EVIDENCE` 并显示最新官方修订及被替代版本。

### 6.4 隐私边界

公开名单只用于识别流程阶段、人数和岗位结果，不默认结构化保存姓名、身份证号、手机号或准考证号。原始公开工件按证据归档，面向用户的 API 不返回无关个人信息。

## 7. 政策证据与 2027 届规则

### 7.1 政策层级

政策按 `NATIONAL → ZHEJIANG → HANGZHOU → DISTRICT → ORGANIZATION` 建立辖区和适用范围。下级公告可增加具体条件，但不能静默覆盖上位政策；冲突时必须提示人工核实。

### 7.2 政策类型

至少支持：

- `GRADUATE_STATUS`：2027 届、择业期、同期毕业留学生；
- `OVERSEAS_DEGREE`：境外学历、留服认证和认证完成时间；
- `EMPLOYMENT_STATUS`：未落实工作单位、劳动合同和档案口径；
- `SOCIAL_SECURITY`：社保缴纳是否影响应届身份；
- `AGE`：年龄上限和计算基准日；
- `MAJOR_CATALOG`：计算机科学与技术、软件工程、人工智能、数据科学等专业目录；
- `MAJOR_EQUIVALENCE`：境外专业名称与国内目录的人工核实流程；
- `WORK_EXPERIENCE`：经历截止日和证明材料；
- `PROFESSIONAL_TITLE`：中级职称、取得方式和适用岗位；
- `EXAM_POLICY`：笔试科目、开考比例、成绩和递补规则。

### 7.3 政策来源

政策工件只接受国家部委及留学服务机构、浙江省、杭州市、区县政府/人社/考试机构和招聘单位官方页面。第三方解释只能作为发现线索。

每条规则保存：适用辖区、适用单位/招聘类型、有效期、发布日期、替代关系、原文片段、官方 URL、内容指纹和人工核验状态。

### 7.4 候选人硬资格输出

系统对每个岗位分别输出：

- 是否接受硕士、是否硬性要求博士；
- “计算机科学与技术”是否直接出现在专业要求中；
- 2027 年毕业是否符合应届窗口；
- 境外毕业时间和留服认证应在何时完成；
- 劳动合同、工作单位、档案或社保是否影响资格；
- 年龄按哪个日期计算以及候选人是否满足；
- 工作经历、中级职称、论文和项目分别是硬条件、加分项还是无关；
- 每个结论的证据、置信度和待确认动作。

境外专业与国内目录的等同性不能由 LLM 自动判为满足。公告只写国内专业代码而未说明境外专业时，输出 `NEEDS_CONFIRMATION`，并给出咨询单位所需的问题和电话证据。

## 8. 推荐与周报规则

### 8.1 准入顺序

推荐前按以下顺序处理：

1. 排除明确博士硬门槛；
2. 排除派遣、短期项目、实习、教师、纯行政和明显无关岗位；
3. 执行年龄、学历学位、专业、应届、境外学历、社保/就业、经历和职称硬资格；
4. 对未知硬资格标记 `VERIFY_FIRST`，不能显示为可报；
5. 对通过或条件通过的岗位计算适配、稳定、机会、成长、未来和准备成本。

### 8.2 排序

杭州内部优先级：

1. 明确事业编制专业技术岗；
2. 科研院所/高校/医院正式工程技术与信息化岗；
3. 政府直属信息中心、数据中心和数字政府技术岗；
4. 政府强背景平台和国企正式技术岗；
5. 用工身份未知但值得核实的岗位。

“计算机科学与技术”直接匹配、明确接受硕士、接受 2027 届/同期境外毕业生、年龄符合且无社保阻断的岗位获得显式标签，但标签不能覆盖其他硬性不合格项。

### 8.3 周报内容

每个值得关注的岗位显示：单位、地区、用工性质、岗位方向、学历、专业、年龄、硕士/博士要求、应届范围、境外学历与留服、未就业/社保、经历、职称/论文/项目、笔试、面试、截止时间、官方来源和下一步动作。

周报只包含：

- 新增高匹配岗位；
- 资格或用工性质发生重要变化的岗位；
- 14 天内截止的已关注岗位；
- 2027 届提前招聘或预告；
- 会改变候选人资格的重要政策变化。

无上述内容时返回明确的空结果说明。

## 9. 数据模型

本期预计新增或扩展：

- `recruitment_notice`：通知身份、类型、标题、发布日期、官方 URI、内容指纹和处理状态；
- `recruitment_notice_link`：通知与招聘事件、岗位的关联、依据和审核状态；
- `policy_source`：政策发布机关、辖区、可信级别和调度配置；
- `policy_document`：原始政策、版本、有效期、替代关系和证据；
- `policy_rule`：扩展为版本化、可按辖区和招聘类型匹配的结构化规则；
- `policy_change`：规则新增、修订、废止及对候选人的影响；
- `source_scope`：来源的地理、组织和路线覆盖声明；
- `weekly_career_digest`：生成时间、观察窗口、岗位变化、政策变化和空结果原因。

现有 `acquired_document`、`source_crawl_run`、`source_year_coverage`、`artifact_import_failure`、`recruitment_event`、`job_posting` 和字段证据表继续复用。数据库迁移只允许前向兼容，不重写既有历史迁移。

## 10. 错误处理

错误至少区分：

- 来源入口/分页合同变化；
- 远程访问失败；
- 文档下载或解析失败；
- 重复表头、合并单元格等行级 Excel 错误；
- 通知类型不确定；
- 生命周期事件无法关联；
- 政策辖区或有效期不确定；
- 政策规则冲突；
- 资格结论缺少候选人事实。

单个附件或通知失败不得把整个来源显示成“不可访问”。来源健康、年度覆盖、招聘处理、生命周期处理和政策处理分别展示状态。

## 11. 测试策略

所有生产行为先写失败测试，再写最小实现。

测试至少覆盖：

- 重复打印表头不会生成伪岗位或部分失败；
- 成绩/面试/体检/公示公告被分类为生命周期通知，不生成新岗位；
- 同一事件的不同通知可稳定关联且复跑幂等；
- 模糊批次不会自动错误合并；
- 公示名单 API 不暴露无关个人信息；
- 2027 届境外毕业生规则按发布日期和有效期匹配；
- 留服未完成、专业等同性和社保状态未知时输出条件式或待确认结论；
- “计算机科学与技术”直接匹配标签来自原始专业证据；
- 博士硬门槛、派遣和短期项目不会进入推荐；
- 一周无岗位和政策变化时返回明确空报告；
- 来源 2024—2026 回采与连续增量复跑不重复生成数据；
- 网络或单工件失败保留上次成功事实且不制造虚假下线。

离线合同测试使用脱敏官方夹具。真实官网冒烟作为显式验收，不进入每次单元测试；真实访问失败不得通过放宽 TLS、改用不安全 HTTP 或伪造完成状态解决。

- 扩展杭州来源目录和 `source_scope`；
- 接入已有通用适配器可覆盖的区县、主管部门和单位官网；

### Slice B：招聘生命周期

- 建通知类型、关联和状态更新模型；
- 取消丢弃成绩/复审/面试/体检/公示的行为；
- 对现有五个来源先回采生命周期通知；
- 在岗位详情和周报展示考试与录用流程。

### Slice C：2027 政策证据

- 建政策来源、文档、规则版本和变化模型；
- 采集国家/浙江/杭州对境外应届、留服、社保、年龄和专业目录的官方规则；
- 将政策规则与候选人和岗位资格逐条关联；
- 输出 2027 资格风险与咨询动作。

### Slice D：重点单位扩展与周报

- 接入高校、医院、科研院所和国企/数字平台；
- 完成 2024—2026 历史回采和 2027 前瞻监控；
- 生成只包含重要变化的杭州周报；
- 用真实候选人重新计算推荐。

每个 Slice 必须独立通过测试和真实数据验收后才能进入下一个，不允许仅登记 URL 就宣称完成。

## 13. 验收标准

本期完成必须同时满足：

1. 杭州十个 P0 区县均存在官方来源配置和可审计运行状态；
2. 政府综合、主管部门、高校、医院、科研院所和国企/平台六类来源都有至少一个真实可运行样本；
3. 当前 20 个核心目录来源中的杭州目标全部得到真实状态，且新增来源不以配置代替连接验收；
4. 2024—2026 历史覆盖按来源逐年展示，缺失必须明确而非推断为零招聘；
5. 成绩、复审、笔试、面试、体检、考察、公示和聘用通知不再被标题过滤器丢弃；
6. 至少三个真实招聘事件形成从公告到一个或多个后续阶段的生命周期链；
7. 2027 届、境外学历/留服、未落实工作单位/社保、年龄和专业目录均有版本化官方政策证据或明确未找到状态；
8. 每个推荐岗位展示用户要求的完整字段；缺失字段显示“官方未明确/待确认”，不能生成推测值；
9. 明确排除的岗位不进入推荐，但可以在原始历史库中审计；
10. 一周没有高匹配岗位时，系统只报告重要政策变化或明确空结果；
11. 相同输入连续运行不产生重复公告、岗位、通知或政策；
12. 全量后端、前端、迁移、API、真实浏览器和官方 HTTPS 冒烟验收通过；
13. 用户画像重新计算后可以输出杭州 T1/T2/T3 分池清单、2027 资格风险和下一步动作；
14. 系统不得把单个附件部分失败显示成整个来源采集失败。

## 14. 非目标

- 本期不接入江苏、福建、广东和浙江其他城市；
- 不绕过登录、验证码、访问控制或网站条款；
- 不自动报名或投递；
- 不采集与职业决策无关的名单个人信息；
- 不用第三方内容替代官方资格证据；
- 不用 LLM 自动确认境外专业等同性、应届资格或事业编身份；
- 不因来源数量增加而引入微服务、Kafka、Elasticsearch或复杂工作流引擎。
