# Phase 5A：半体制职业规划工作台

## 交付目标

`/plan` 把候选人画像、2024—2026 官方历史岗位和 2027 毕业时间线整合为一份可追溯的个人规划。它回答“现阶段能看哪些路线、资格何时变化、年龄窗口还有多久、往年何时招聘和考试、现在应准备什么”，不把历史数量包装成录取概率。

## 使用入口

启动 Career OS 后打开：

```text
http://localhost:8080/plan
```

页面按以下顺序呈现：

1. 当前结论与优先路线；
2. 境外硕士在读、硕士待认证、硕士已认证三种资格场景；
3. 2024—2026 官方历史岗位与独立招聘事件数量；
4. 事业单位信息技术岗、高校医院信息化岗、科研技术支撑岗、政府国企数字化岗四条路线，以及每条路线在三种场景下的可报、条件可报、待确认和不可报数量；
5. 2027—2031 年 35、38、40 周岁窗口；
6. 历史报名、笔试、专业测试、面试阶段及其证据状态；
7. 学历认证、政治面貌、工作经历证据和数据覆盖风险；
8. 从当前到第二个完整招聘周期的行动时间线；
9. 可下钻的代表岗位站内完整详情，以及保留的官方公告和附件链接。

## 资格规则

- 年龄使用完整生日和公告参考日按实龄计算。页面中的未来春季参考日是规划假设，正式报名必须以当年公告为准。
- 2027 境外硕士取得证书前属于“境外硕士在读”；取得证书但留服认证未完成时属于“硕士待认证”；两者完成后才属于“硕士已认证”。已完成本科仍参与具体岗位的最低学历判断，但不再覆盖当前在读状态。
- 预计毕业年份等于目标年份时，系统独立输出 `TARGET_YEAR_GRADUATE`。这表示进入目标年度应届生候选轨道，不等于所有应届岗位自动可报；学位、留服认证、未就业/社保要求和公告截止时点仍逐项判断。
- 历史岗位同时输出 `historicalActual` 与 `targetYearAnalog`：前者回答历史公告当时能否报名，后者把相对届别规则投影到目标年份，用于寻找 2027 同类机会。两者不得混成一个结论。
- 工作经历只计算画像中有起止日期和核验状态的记录。系统不会从简历空档或在读时间自动推断全职经历。
- 多段已核验全职经历先合并重叠区间，再按完整年计算，不会重复累计。
- 政治面貌未知时，党员限定岗位保持“待确认”，不会默认通过。
- LLM 不参与年龄、学历、经历年限等硬资格计算，也不能覆盖 Java 确定性规则。
- 未确认事实产生“待确认”或“条件可报”，不会因为资料空白直接判定符合或不符合。

## 路线指数

路线指数由五项确定性证据分加权得到：当前资格准备度 30%、已核验经历优势 25%、正式用工占比 20%、历史供给强度 15%、准备内容复用 10%。页面可以展开查看每项分数、权重和依据。没有证据的工作经历优势计 0 分并标记为未形成证据，不会使用主观补分；该指数用于路线比较，不是录取概率。

## 历史数据口径

规划只查询 2024—2026 年、当前仍保存在官方证据库中的本科/硕士层级目标技术岗位，并排除博士后、教学、临床、护理、销售、劳务派遣和项目制岗位。岗位按岗位 ID 去重，招聘次数按招聘事件 ID 去重。

页面同时显示 `source_year_coverage` 覆盖账本：

- `COMPLETE`：该来源年度扫描完成；
- `NO_TARGET_RECORDS`：扫描完成但没有目标记录；
- `PARTIAL`：只完成部分页面或附件；
- `NOT_DISCOVERED`：尚未完成发现；
- `ACCESS_FAILED`：访问失败，需要重试或人工处理。

只要存在未完成来源，页面会明确显示“数据尚未补齐；缺失来源不得解释为零招聘”。目标来源目录当前登记 20 个浙江/杭州官方入口，并分别标记已接入、部分接入、访问失败和未接入；登记进目录不等于已经采集。覆盖不足的路线进入 `NOT_COVERED` 或 `LIMITED` 状态，不能用零分与已覆盖路线直接比较。

规划采用三层覆盖口径：

- `configuredCoverage`：已配置的来源年度是否完成扫描；
- `targetMarketCoverage`：20 个目标官方来源的接入状态及按路线汇总；
- `analysisCoverage`：本次结论实际使用的来源、招聘事件、岗位和证据完整岗位数量。

兼容字段 `dataCoverage.complete` 与 `configuredCoverage.complete` 只表示当前已配置来源年度完成，不表示杭州/浙江半体制目标市场已经完整覆盖。

## API

```http
GET /api/v1/candidates/{candidateId}/career-plan?targetYear=2027&asOf=2026-08-22
```

- `targetYear` 可省略，默认是 `asOf` 的下一年；允许服务器当前年份至未来五年。
- `asOf` 可省略，默认服务器当天；不允许未来日期。
- 返回值包含候选人快照、当前学历阶段、目标年度应届轨道、历史实际/目标年份类比资格、路线、年龄窗口、招聘流程、考试证据状态、年度汇总、风险、行动项、三层覆盖、生成时间和算法版本。
- `examSummary` 以独立招聘事件为分母，分别统计笔试、专业测试和面试的 `CONFIRMED`、`NOT_REQUIRED`、`NOT_PUBLISHED`、`NOT_COLLECTED`、`PARSE_FAILED`、`REVIEW_REQUIRED` 和 `UNKNOWN`。未采集不得显示为“无笔试”。
- `recommendedRoutes[*].priorityScore` 在来源未覆盖或读取失败时允许为 `null`；客户端必须结合 `rankingState` 和 `rankingReason` 展示，不能把空分数显示为 0 分。
- 旧字段继续保留供现有客户端读取；新客户端应优先使用顶层 `configuredCoverage`、`targetMarketCoverage` 与 `analysisCoverage`。
- 当前算法版本是 `career-plan-v3`。

## 已知边界

- 历史供给表示“已采集且符合规划查询口径的记录”，不是完整市场岗位总量，也不是个人可报名岗位数。
- 代表岗位使用独立的 `/jobs/{jobId}` 历史详情页，不受机会池分页或准入状态限制；最终报考条件仍以保存的官方公告、附件和原始链接为准。
- 未来公告日期不会由历史月份伪造。未发布的新公告只显示预计关注窗口，不显示虚构截止日期。
- 预计毕业月或认证完成日未确认时，场景切换日期保持为空，不默认使用 6 月或“毕业后一个月”。
- 画像中的工作经历当前保持空白，直到用户提供真实起止日期与证明类型。
